# Ramadan seasonal programs
> How **Quran.com frontend (github.com/quran/quran.com-frontend-next)** implements this feature. Sources read from a shallow clone @ main (2026-08-23); repo-relative paths cited throughout.

## 1. What the user sees
- A family of seasonal, mostly static landing pages: `/ramadan` ("Ramadan Tools, Programs and Features" hub in `src/pages/ramadan/index.tsx`), `/ramadanchallenge` (30-day Surah Al-Mulk memorization challenge in `src/pages/ramadanchallenge/index.tsx`), `/ramadan2026` (year hub linking challenge, goal setting, learning plans), `/what-is-ramadan` (shareable explainer with Arabic/Swahili variants in `WhatIsRamadanArabic.tsx` / `WhatIsRamadanSwahili.tsx`), and `/beyond-ramadan` ("keep growing year-round").
- Each page is anchored sections + CTA buttons: "Set Your Goal", "Enroll Now" for learning plans (`getCourseNavigationUrl('mindful-fasting')`, `'preparing-our-hearts-for-ramadan'`), WhatsApp/Telegram join buttons, and a donor appeal.
- The challenge page shows a live "N+ people around the world have joined" counter plus a "Join the Surah Al-Mulk Challenge" enroll button that reflects signed-in state.

## 2. Architecture & key files
- Pages are plain `NextPage` components with hardcoded copy (the eslint headers disable `i18next/no-literal-string` deliberately) — no CMS fetch in `getStaticProps` on any of these five pages; content ships in the bundle.
- Shared presentational helpers live in `src/components/RamadanActivity/`: `InlineLink.tsx`, `ReadMoreCollapsible/index.tsx` (truncates long review lists behind a toggle), `RamadanActivityHero/index.tsx`.
- Enrollment logic lives in `src/components/RamadanChallenge/`: `UnauthEnrollButton.tsx`, `EnrollButtonNotification.tsx`, `EnrollmentCount.tsx`.
- SEO is first-class: every page wraps itself in `NextSeoWrapper` with canonical URL via `getCanonicalUrl(lang, PATH)`, hreflang alternates via `getLanguageAlternates(PATH)`, and per-page OG images generated by `src/lib/og` (`getRamadanChallengeOgImageUrl`, `getPreparingForRamadanOgImageUrl`).

## 3. Data flow
- Only two dynamic touchpoints. `UnauthEnrollButton.tsx` branches on `useIsLoggedIn()`: guests get a button that redirects to `getLoginNavigationUrl(router.asPath)`; logged-in users are wrapped in `HeadlessServiceProvider` (Novu, `src/components/Notifications/hooks/useHeadlessService.tsx`) so `EnrollButtonNotification` can subscribe to reminder notifications while enrolling.
- Enrollment itself calls `addReadingGoal(...)` from `src/utils/auth/api.ts` with `GoalCategory.RAMADAN_CHALLENGE` — i.e. joining the challenge *is* creating a reading goal on the account backend, surfaced by the `useGetRamadanChallengeStatus` hook.
- `EnrollmentCount.tsx` uses SWR against `makeReadingGoalCountUrl({ type: GoalCategory.RAMADAN_CHALLENGE })` → `getReadingGoalCount`; it returns `null` when count < `MINIMUM_ENROLLMENT_COUNT = 500` (a social-proof floor) or shows a Skeleton while loading.
- The daily lesson delivery is off-platform entirely: email ("check your promotions or spam folder") plus `EXTERNAL_ROUTES.RAMADAN_CHALLENGE_WHATSAPP/TELEGRAM` deep links; lesson content derives from the Sanity-hosted learning plan at `/learning-plans/30-transformative-days-with-surah-al-mulk-learn-reflect-memorize`.

## 4. Storage & network
- No local persistence specific to these pages. Enrolled state lives server-side on the account backend (reading-goal API) and notification state in Novu; both are fetched client-side per visit.
- All CTAs are instrumented with `logButtonClick` keys like `ramadan_challenge_join_whatsapp`, `guest_ramadan_challenge_${section}`, `${section}_preparing_for_ramadan_cta` for analytics.
- Pages force `dir="ltr"` on the container regardless of locale — copy is English-only by design here.

## 5. Why it is built this way ON THIS PLATFORM
- Discovery happens through search and social sharing, so these pages optimize for SEO/OG cards rather than app-style UI; static hardcoded copy means zero backend dependency and instant TTFB during the seasonal traffic spike.
- Seasonality is handled by adding new route folders per year (`ramadan2026`) and cross-linking them, not by feature flags — old URLs keep their accumulated search equity.
- Because enrollment must survive across devices and outlive the month, it reuses the existing account-backed reading-goal system instead of new storage; the challenge is "just" a themed reading goal plus an email drip run outside the web app.

## 6. Edge cases & offline behavior
- Logged-out users clicking enroll never lose context — the login redirect carries `router.asPath` back.
- Counter hides itself below 500 enrollees and shows a skeleton rather than a low or unknown number.
- Offline, everything already rendered keeps working (pure markup); only the counter/enroll state degrades since there is no service-worker fallback data for those endpoints beyond next-pwa's generic NetworkFirst API cache (`pwa-runtime-config.js`). No dedicated offline handling was found within budget for these pages.
