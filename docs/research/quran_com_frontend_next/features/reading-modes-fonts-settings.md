# Reading modes and Arabic typography settings
> How **Quran.com frontend (github.com/quran/quran.com-frontend-next)** implements this feature. Sources read from a shallow clone @ main (2026-08-23); repo-relative paths cited throughout.

## 1. What the user sees
A settings drawer with a three-way reading-mode switch — "Verse by Verse" (translation), "Reading" (pure Arabic mushaf pages), "Reading with one translation" (`ReadingPreference` enum, `types/QuranReader.ts`) — plus a font-family switch (Uthmani / IndoPak / Tajweed), conditional sub-controls: a font-style select of Madani V1 (`code_v1`), Madani V2 (`code_v2`) or QPC Hafs (`qpc_uthmani_hafs`) for Uthmani; a lines-per-page select (15/16 lines) for IndoPak; a "show tajweed rules" checkbox for the Tajweed mushaf. A counter scales Arabic text from `MINIMUM_FONT_STEP = 1` to `MAXIMUM_QURAN_FONT_STEP = 10`.

## 2. Architecture & key files
`src/components/Navbar/SettingsDrawer/QuranFontSection.tsx` is the typography UI; it dispatches into two RTK slices: `src/redux/slices/QuranReader/styles.ts` (`QURAN_READER_STYLES`: `quranFont`, `mushafLines`, nine independent per-content-type font scales, `showTajweedRules`, derived `isUsingDefaultFont`) and `src/redux/slices/QuranReader/readingPreferences.ts` (`READING_PREFERENCES`: `readingPreference`, word-by-word display/tooltip content, `selectedReadingTranslation`, `lastUsedReadingMode`). The font→mushaf contract is the static map `QuranFontMushaf` in `types/QuranReader.ts` (`MadaniV2 → QCFV2`, `IndoPak → Indopak`, `QPCHafs → KFGQPCHAFS`, …), which flows into API calls through `getMushafId`/`getDefaultWordFields` in `utils/api.ts`. Mode switching happens in `QuranReaderView.tsx`, which swaps `TranslationView` vs dynamically-imported `ReadingView`; a quick toggle component lives in `QuranReader/ReadingPreferenceSwitcher/`.

## 3. Data flow
Every control calls one funnel: `usePersistPreferenceGroup().onSettingsChange(key, value, action, undoAction, PreferenceGroup.QURAN_READER_STYLES | .READING)` — it dispatches the redux action immediately (optimistic UI) and pushes the whole preference group to the account backend for logged-in users. Font changes additionally `dispatch(resetLoadedFontFaces())` so cached `@font-face` state is invalidated. On login/device sync, each slice's `syncUserPreferences` extraReducer merges remote values; `styles.ts` recomputes `isUsingDefaultFont` against locale defaults and `readingPreferences.ts` runs legacy fields through `getWordByWordFieldsFromRemote`. The active mode then determines rendering: `selectValidatedReadingTranslation` guards the single-translation id against orphaning when users deselect it.

## 4. Storage & network
Both slices are whitelisted in redux-persist's localStorage store, so choices survive reloads anonymously; authenticated users get server-side sync grouped by `PreferenceGroup` (the same payload shape both sides understand). Locale-aware defaults come from per-language modules loaded via `require()` in `src/redux/defaultSettings/util.ts` (`getQuranReaderStylesInitialState(locale)`) — e.g. `locales/id.ts` defaults Indonesian readers to `QuranFont.IndoPak`, while the global base default is Madani V2 with `MushafLines.SixteenLines`. Actual glyph rendering: Uthmani fonts are QCF *page-based* webfonts — `hooks/useQcfFont.ts` injects one `@font-face` per mushaf page as verses load, whereas IndoPak/QPC/Tajweed are ordinary text fonts fetched by `FontPreLoader`. Unavailable fonts fall back to `FALLBACK_FONT = QuranFont.QPCHafs`.

## 5. Why it is built this way ON THIS PLATFORM
Arabic script on the web has no native text stack to lean on, so "font choice" is really a choice between font technologies: pre-shaped QCF glyph fonts (pixel-perfect mushaf pages, but per-page files that must be lazily injected) versus Unicode text fonts (flowable, scalable, needed for IndoPak line layouts). That split explains why switching fonts must reset font-face caches and why `mushafLines` exists only for IndoPak. Persisting to localStorage first keeps the UI instant despite network round-trips, while backend sync solves the web's inherent device-hopping problem. Locale-derived defaults (IndoPak for Indonesia) reflect the browser being locale-first: the app can't read an OS-level region setting like a native app can, so it infers intent from the UI language.

## 6. Edge cases & offline behavior
The documented hydration race (see `TranslationView/TranslationViewVerse/hooks/useDedupedFetchVerse.ts`) bites here too: request keys embed font/mushaf-lines, so SWR keys generated before persist-rehydration mismatch post-rehydration ones; gating on `selectIsPersistGateHydrationComplete` fixes blank verses while SSR still ships page 1 via `fallbackData`. `setMushafLines`/`setQuranFont` recompute `isUsingDefaultFont` on every change so analytics and reset flows know true defaults. `resetSettings` restores per-locale defaults rather than hardcoded ones. Offline, persisted slices keep all typography intact; only un-cached QCF page fonts need the network (and are precached by the service worker's Workbox font rules once seen).
