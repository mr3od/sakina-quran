# Word-by-word study tools
> How **Quran.com frontend (github.com/quran/quran.com-frontend-next)** implements this feature. Sources read from a shallow clone @ main (2026-08-23); repo-relative paths cited throughout.

## 1. What the user sees
A "Word by Word" block in the settings drawer (`src/components/Navbar/SettingsDrawer/WordByWordSection.tsx`, ~400 lines) with four controls: a language `Select` for the WBW locale; an "On click" row whose `CheckboxChip` toggles whether tapping a word plays its recitation audio; an "On hold/hover" row choosing tooltip content (translation and/or transliteration); and a "Below word" row choosing inline content shown under each word. A font-size `Counter` completes the section, and a footer credits quranwbw.com as the data source.

## 2. Architecture & key files
- Config UI: `WordByWordSection.tsx` writing into the reading-preferences slice (`setSelectedWordByWordLocale`, `setWordClickFunctionality`, `setWordByWordTooltipContentType`, `setWordByWordInlineContentType`, `setWordByWordDisplay`).
- Enums in root-level `types/QuranReader.ts`: `WordByWordType { translation, transliteration }`, `WordClickFunctionality { PlayAudio='play-audio', NoAudio='no-audio' }`, `WordByWordDisplay { INLINE, TOOLTIP }`.
- Rendering: `src/components/dls/InlineWordByWord/index.tsx` (37 lines) consumed by `src/components/Verse/PlainVerseText/PlainVerseTextWord/index.tsx` and `src/components/AyahWidget/QuranWidget.tsx`; reading-mode hover/tap lives under `src/components/QuranReader/ReadingView/WordByWordVerseAction/`.

## 3. Data flow
The locale list is fetched client-side via `DataFetcher` + `makeWordByWordTranslationsUrl(lang)` → `/resources/word_by_word_translations?language=`, deduped by `isoCode` with lodash `uniqBy` and labeled through `getLocaleName`. Crucially, the chosen locale is also baked into default verse-fetch params: `src/utils/apiPaths.ts` line 44 seeds `wordByWordLocale` from `getReadingPreferencesInitialState(currentLocale).selectedWordByWordLocale`, so word data arrives already localized inside verses responses and changing the locale re-keys the SWR URL. On change, the component persists via `onSettingsChange(..., PreferenceGroup.READING)` then shallow-pushes `QueryParam.WBW_LOCALE` onto the router so a configured view stays shareable/bookmarkable.

## 4. Storage & network
All WBW preferences live in `readingPreferences` slice state (`selectReadingPreferences`), whitelisted into localStorage by redux-persist in `src/redux/store.ts`; the slice tracks `isUsingDefaultWordByWordLocale` and merges remote values field-by-field in its `syncUserPreferences` reducer (e.g. `remote.selectedWordByWordLocale ?? state...`). Font scale goes to `styles` slice (`increase/decreaseWordByWordFontScale`, bounded by `MINIMUM_FONT_STEP`/`MAXIMUM_WORD_BY_WORD_FONT_STEP`) persisted under `PreferenceGroup.QURAN_READER_STYLES`. Word text itself costs zero extra requests when inline (part of the verses payload); tooltips reuse the same payload on hover/tap rather than fetching per word. All toggles fire `logEvent`/`logValueChange` calls.

## 5. Why it is built this way ON THIS PLATFORM
On the web there is no bundled string table per language, so the WBW catalog is an API resource selected per ISO code and the locale travels as a URL parameter — this keeps verse HTML cacheable per (font, mushaf-lines, translations, WBW-locale) combination in both ISR and the service worker, at the cost of a refetch when the locale flips. Display is derived, not stored: `wordByWordDisplay` (INLINE/TOOLTIP membership) is recomputed automatically from which content checkboxes are on (`onInlineTranslationChange` auto-adds INLINE when any content is checked and removes it when none remain), preventing impossible states like inline mode with nothing to show. `InlineWordByWord` reads font scale straight from Redux instead of props so any consumer across reader/widget/collections stays consistent. Tap-to-play audio reuses the existing XState audio player rather than a bespoke player.

## 6. Edge cases & offline behavior
The language `Select` is disabled entirely when neither tooltip nor inline content includes a translation (`shouldDisableLanguageSelect`) since a locale would have nothing to localize. Undo actions are passed alongside every preference change so optimistic server sync can roll back. Offline, previously fetched verses keep their inline words because they arrived embedded in the verses response cached by the next-pwa service worker; switching to an unseen WBW locale offline simply fails the refetch and falls back to SWR error states — there is no pre-packaged WBW database, matching the web platform's no-local-storage-of-content approach.
