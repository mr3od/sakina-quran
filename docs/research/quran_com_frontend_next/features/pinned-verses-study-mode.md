# Pinned verses and study/memorization mode
> How **Quran.com frontend (github.com/quran/quran.com-frontend-next)** implements this feature. Sources read from a shallow clone @ main (2026-08-23); repo-relative paths cited throughout.

## 1. What the user sees
Pinning a verse (via `PinMenuItem` in `src/components/QuranReader/ReadingView/WordActionsMenu/`) adds it to a persistent bar above the reader (`src/components/QuranReader/PinnedVersesBar/`, with `VerseTag`, `PinnedVersesContent`, `PinnedVersesMenu`). The bar offers copy (`copyPinnedVerses`), add-a-note (`AddNoteModal`), save-to-collection and load-from-collection modals, and a "Compare" button that opens study mode over the first pinned verse. Study mode is a full-screen modal (`src/components/QuranReader/ReadingView/StudyModeModal/`) with tabs — tafsir, reflections, related verses, lessons, answers, qiraat, hadith and "layers" — plus a `SearchableVerseSelector`, `WordNavigationBox`, `PinnedVersesSection` and per-tab `FontSizeControl`.

## 2. Architecture & key files
- `src/redux/slices/QuranReader/pinnedVerses.ts`: `PinnedVerse { verseKey, chapterNumber, verseNumber, timestamp, serverId? }`; actions `pinVerse` (deduped by verseKey), `pinVerses` (bulk, `timestamp + index` ordering), `unpinVerse`, `clearPinnedVerses`, `setServerIds`, `setPinnedVerses`; memoized selectors incl. `selectPinnedVerseKeysSet`.
- `src/redux/slices/QuranReader/studyMode.ts`: global modal state `{ isOpen, isSsrMode, verseKey, activeTab, highlightedWordLocation, previousState, showPinnedSection }`.
- Sync: `src/hooks/usePinnedVerseSync.ts` and `src/hooks/auth/pinnedVersesSync.ts`; container `src/components/QuranReader/StudyModeContainer.tsx`.

## 3. Data flow
Pinning is optimistic: `usePinnedVerseSync.pinVerseWithSync` dispatches `pinVerse(verseKey)` locally and broadcasts to other tabs via `broadcastPinnedVerses(PinnedVersesBroadcastType.PIN)`, then if logged in calls `addPinnedItem({ targetType: PinnedItemTargetType.Ayah, targetId: verseKey, metadata: { sourceMushafId, key, verseNumber } })` from `src/utils/auth/api.ts`, storing the returned backend id with `setServerIds`. Failure rolls back the local pin, shows a Toast with a Retry action and logs to Sentry. On login/global sync, `mergeAndSyncPinnedVerses` pulls `getPinnedItems`, converts DTOs (`serverItemToLocal`/`localToSyncPayload`), merges by verseKey sorted by timestamp, and maps server ids back into local state. Study mode state is deliberately centralized in Redux so all entry points ("QuranWord, TranslatedAyah, BottomActions, EndOfSurahSection" per the slice comment) behave identically; `saveAndCloseStudyMode` stashes `previousState` for `restoreStudyMode`.

## 4. Storage & network
`PINNED_VERSES` is whitelisted in the redux-persist config of `src/redux/store.ts` (line 81), so anonymous users keep pins across sessions in localStorage; `STUDY_MODE` is intentionally not persisted — it is ephemeral UI state. Logged-in users get server persistence through the same JWT-auth'd preference/item APIs used by bookmarks. The tafsir deep-link path reuses this stack for SSR: `src/pages/[chapterId]/tafsirs/[tafsirId].tsx` renders `StudyModeSsrContainer` with `initialTab={StudyModeTabId.TAFSIR}` inside an SWR `fallback` seeded by `getStaticProps`. The modal itself is loaded with `dynamic(() => import('./ReadingView/StudyModeModal'), { ssr: false })` in `StudyModeContainer.tsx`, closing dispatches `closeStudyMode()` + `clearAllHighlights()`.

## 5. Why it is built this way ON THIS PLATFORM
The web has no background sync or local database, so pins use the repo's established three-layer pattern: localStorage for instant offline truth, cross-tab broadcast for multi-tab consistency, and best-effort REST sync with rollback for accounts. The bar doubles as a lightweight collection builder (save/load to server collections, gated behind `isLoggedIn()` → redirect to `getLoginNavigationUrl`). Study mode is one modal reused for many purposes (tafsir reading, reflections, recall practice) because SEO landing pages need its content renderable on the server — hence `openStudyModeSsr` and the SSR container variants under `StudyModeModal/`. Recall testing is implemented as collapsed-by-default content rather than a separate mode: the Layers tab starts at `LayerMode.Collapsed` and expands alternative word translations on demand (`GroupPanel`/`GroupToken`/`LayerControls`), while `StudyModeTafsirTab` passes `showArabicText={false}` and the Hadith tab hides Arabic behind a show/hide toggle.

## 6. Edge cases & offline behavior
Duplicate pins are no-ops; bulk loads preserve order via timestamp increments. Network failures never lose local data — rollback + retry toast + Sentry metadata (`transactionName: 'usePinnedVerseSync.pin'`). Unauthenticated users can pin and copy but get redirected when saving/loading collections. Offline pins live entirely in localStorage until a logged-in session reaches the server, where merge-by-verseKey prevents duplicates. Closing the modal clears highlights so no selection state leaks back into the reader.
