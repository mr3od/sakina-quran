# Share verse text
> How **Quran for iOS (github.com/quran/quran-ios)** implements this feature. Sources read from a shallow clone @ main (2026-08-23); repo-relative paths cited throughout.

## 1. What the user sees
Long-pressing an ayah (or dragging across a range) in the mushaf opens the ayah menu (`Features/AyahMenuFeature/Sources/AyahMenuViewController.swift` + `AyahMenuUI`), anchored near the pressed verse. Choosing Share hands a formatted plain-text block — Arabic verses with ornate verse numbers, optionally the currently selected translations, and a citation footer — to the system `UIActivityViewController` share sheet, presented as a popover anchored to the exact tap point on iPad. A sibling Copy action places the same text on `UIPasteboard.general`.

## 2. Architecture & key files
- `Features/AyahMenuFeature/Sources/AyahMenuViewModel.swift` — `share()` (line ~259) and `copy()` (~248) both call `retrieveSelectedAyahText()`, which awaits `deps.textRetriever.textForVerses(deps.verses)`; `Deps` captures `sourceView: UIView` and `pointInView: CGPoint` at menu construction for popover anchoring.
- Listener protocol `AyahMenuListener.shareText(_ lines: [String], in:at:)` is implemented by `QuranInteractor.shareText` (`Features/QuranViewFeature/Sources/QuranInteractor.swift:247`) which dismisses the menu and forwards to its presenter.
- `Features/QuranViewFeature/Sources/QuranViewController.swift:157` builds `UIActivityViewController(activityItems: lines, applicationActivities: nil)`.
- Text assembly lives in Domain: `Domain/QuranTextKit/Sources/ShareableText/ShareableVerseTextRetriever.swift`.

## 3. Data flow
`share()` spawns a `Task`, retrieves `[String]` lines, joins them with `\n` into one string, and calls the listener with `[joined]`. `ShareableVerseTextRetriever.textForVerses` runs two concurrent loads with `async let`: `arabicScript(for:)` and `translations(for:)`. Arabic comes from `GRDBQuranVerseTextPersistence(mode: .share, fileURL:)` — a dedicated share-mode variant of the bundled quran.db, distinct from the display-mode persistence — each verse wrapped in RTL bidi controls and suffixed with `﴿ <Arabic-Indic numeral> ﴾`; all verses are space-joined into one paragraph. Translations are fetched via `QuranTextDataService.textForVerses(_:translations:)` only if `QuranContentStatePreferences.shared.quranMode == .translation`, grouped per translator as `"• <translator name>:"` blocks separated by blank lines. The result is appended with an empty line plus `versesSummary` — e.g. the localized name of "2:255" or "2:255 - 2:260".

## 4. Storage & network
Purely local SQLite reads: the bundled uthmani database (via the `.share`-mode GRDB persistence) and any downloaded translation databases already on disk through `LocalTranslationsRetriever`/`QuranTextDataService`. No network call occurs during sharing, so it works fully offline; translation content simply reflects what was previously downloaded in Settings' translations manager. Nothing about the shared text is persisted by this feature.

## 5. Why it is built this way ON THIS PLATFORM
The repo deliberately ships no share-as-image rendering (verified absent), so sharing is plain text handed to `UIActivityViewController` — iOS provides all destinations (Messages, Mail, Notes, save-to-files) for free, which matches the platform idiom of delegating distribution to the system sheet. Because mushaf pages are pre-rendered images, the Arabic must be re-read from the text database rather than captured from screen; the dedicated `.share` persistence mode exists so the exported script can differ from the on-page rendering. The invisible `\u{202B}`…`\u{202C}` bidi embedding plus Arabic-Indic numerals exist specifically because recipients on LTR devices would otherwise render the ayah backwards. iPad requires an explicit popover source, hence `Deps` snapshots the source view and tap point when the menu is built.

## 6. Edge cases & offline behavior
Failures are swallowed: `share()`/`copy()` use `try? await retrieveSelectedAyahText()`, and retrieval itself wraps errors with `crasher.recordError("Failed to update highlights")` (a copy-pasted reason string inside `AyahMenuViewModel.retrieveSelectedAyahText`) — so a db miss silently does nothing rather than showing an error UI. Translation inclusion depends on current reading mode: in mushaf mode the share contains Arabic + citation only. Multi-verse selections produce one space-joined Arabic paragraph followed by per-verse translation lines. Copy and share share identical composition logic, guaranteeing consistency between clipboard and sheet. The completion handler from `UIActivityViewController.completionWithItemsHandler` is accepted but unused (`completion: {}` at the presenter call site).
