# Word-by-word popover
> How **Quran for iOS (github.com/quran/quran-ios)** implements this feature. Sources read from a shallow clone @ main (2026-08-23); repo-relative paths cited throughout.

## 1. What the user sees
The user long-presses/activates a "word pointer" mode from the more menu: a draggable arrow-shaped pointer appears over the mushaf page, with a circular magnifying-glass lens following the fingertip so the page is readable under the finger. As the pointer's tip sweeps across words, each word under it highlights in place on the page image and a small popover bubble shows that word's translation or transliteration. Releasing the finger hides the lens and popover and flings the pointer to dock at the nearest screen edge with a spring animation.

## 2. Architecture & key files
- `Features/WordPointerFeature/Sources/WordPointerViewController.swift` — pure UIKit overlay: a `ByPassTouchesView` whose `catchTouchesView` is the 44pt pointer (`NoorImage.pointer`, templated + drop shadow), positioned by raw `pointerTop`/`pointerLeft` NSLayoutConstraint constants; a `MagnifyingGlass` view magnifying the pages reference view; one `UIPanGestureRecognizer`; popover rendering delegated to the `Popover_OC` package (`PopoverView.show(to:isUpward:with:)`).
- `Features/WordPointerFeature/Sources/WordPointerViewModel.swift` — tiny `@MainActor` state machine returning a `PanResult` enum (`.none` / `.hidePopover` / `.showPopover(text:)`).
- `Features/WordPointerFeature/Sources/WordPointerBuilder.swift` builds it; activation lives in `Features/QuranViewFeature/Sources/QuranInteractor.swift` (`onIsWordPointerActiveUpdated` toggles `showWordPointer(referenceView: presenter.pagesView)`; the interactor itself implements `WordPointerListener`).
- Hit-testing: `Features/QuranImageFeature/Sources/ContentImageViewModel.wordAtGlobalPoint` + `Model/QuranGeometry/Sources/WordFrameCollection.wordAtLocation`.
- Text lookup: `Domain/WordTextService/Sources/WordTextService.swift`.

## 3. Data flow
Each pan `.changed` event cancels the previous `panningTask` and starts a new `Task { await asyncOnPanned(state:) }` — stale hit-tests can never land out of order. The controller moves the pointer constraints, computes the arrow-tip point (`maxX - 15, minY + 15`), converts it to window coordinates via `view.convert(_:to: nil)`, and calls `viewModel.viewPanned(to:)`. The view model asks its listener `word(at: point)`; the interactor forwards into the image view model which subtracts `imageFrame.origin` then calls `wordFrames.wordAtLocation(localPoint, imageScale: scale)` — a linear scan of flattened word rectangles scaled by `WordFrameScale`, first `contains` wins. If it is a new word the service resolves text (`await service.textForWord(word)`); same-word re-entry returns `.none` so the database is not re-hit while the finger dwells. The result drives `highlightWord(word)` (which flows into `ContentImageViewModel.decorations` as `QuranHighlights.pointedWord` → colored overlay rectangle) and the popover show/hide.

## 4. Storage & network
Fully offline after setup. Word frames come from the GRDB "ayah info" database (`GRDBWordFramePersistence`) fetched per page in `Domain/ImageService/Sources/ImageDataService.wordFrames(_:)`, then normalized by `WordFrameProcessor.processWordFrames`: frames are grouped by line, vertically aligned within lines, neighboring lines unioned vertically, and adjacent frames unioned horizontally so rectangles tile each line with no gaps or overlaps — guaranteeing the finger always lands on some frame. Word texts live in a separate words SQLite db opened by `GRDBWordTextPersistence(fileURL:)`; `textForWord` switches on `WordTextPreferences.shared.wordTextType` between `translationForWord` and `transliterationForWord`. The mode flag persists through the MoreMenu preferences.

## 5. Why it is built this way ON THIS PLATFORM
Because the mushaf ships as pre-baked page images, there is no text layout to query — so interaction is rebuilt entirely from a geometry sidecar database, and the whole feature is a UIKit overlay floating above a SwiftUI-hosted UIPageViewController rather than SwiftUI gestures (a full-screen pan must coexist with the pager's own swipe scrolling, which `ByPassTouchesView` mediates). The Task-per-gesture-event pattern converts an imperative delegate stream into async calls while preserving cancellation semantics on the @MainActor. Docking physics (velocity threshold of 100 pts/s deciding the edge, `velocity.y * 0.3` vertical projection, spring damping 0.7 in `asyncOnPanned(.ended)`) and the magnifying lens offset (`lookingUpward` flips at y < 130, popover placed ±70pt) are hand-tuned UIKit polish that would be hard to reproduce in SwiftUI. Rotation support repositions the pointer proportionally from cached `pointerParentSize` in `viewDidLayoutSubviews`.

## 6. Edge cases & offline behavior
No word at the point (finger off-page or unscaled frames) unhighlights and hides the popover; a missing DB row also yields `.hidePopover` rather than an error. Service throws are swallowed into `crasher.recordError(reason: "Error calling WordTextService")` plus popover hide. Rapid drags never show stale popovers because each new gesture state cancels the prior task before awaiting. The feature only applies to image mode since `word(at:)` resolves through `imagePage?.wordFrames` (nil until the page loads). Popover placement auto-flips upward near the top of the screen, and the pointer is constrained to safe-area insets (`minX`/`maxX` from `view.window?.directionalSafeAreaInsets`) when docking.
