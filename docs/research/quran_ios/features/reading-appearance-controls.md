# Reading display controls (more menu)
> How **Quran for iOS (github.com/quran/quran-ios)** implements this feature. Sources read from a shallow clone @ main (2026-08-23); repo-relative paths cited throughout.

## 1. What the user sees
A compact popover-style panel opened from the reader. Depending on configuration it exposes: Arabic-mode selector (mushaf/translation), translations-selection entry, word-pointer toggle plus pointer type, line-page display options, orientation (device rotation) lock, two-page tablet toggle, vertical-scrolling toggle, and a "Theme settings" disclosure row that opens a second form-sheet with Arabic/translation font-size steppers, an appearance-mode dropdown (auto/light/dark) and a theme-style picker.

## 2. Architecture & key files
- `Features/MoreMenuFeature/Sources/MoreMenuModel.swift` — `MoreMenuModel` (host-provided input: `isWordPointerActive`, `state`) and `MoreMenuControlsState`, where every control has a `ConfigState` of `.alwaysOn` / `.alwaysOff` / `.conditional`. Defaults mark `linePageDisplay` `.alwaysOff` and the rest `.conditional`.
- `Features/MoreMenuFeature/Sources/MoreMenuViewModel.swift` — `@MainActor ObservableObject` holding one `@Published` property per control; every `$publisher.dropFirst().sink` writes straight through to the owning preference singleton.
- `Features/MoreMenuFeature/Sources/views/MoreMenuView.swift` — renders rows conditionally via `isVisible(state.fontSize, ...)`-style checks against `MoreMenuControlsState`; includes `MoreMenuDeviceRotation`, `MoreMenuTwoPages`, `MoreMenuVerticalScrolling`, `MoreMenuLinePageDisplay`, `MoreMenuModeSelector`, `MoreMenuTranslationSelector`, `MoreMenuWordPointer`.
- `Features/MoreMenuFeature/Sources/views/MoreMenuThemeSettings.swift` — `ThemeSettingsController` (UIHostingController form-sheet) + `MoreMenuThemeSettingsView`; `views/MoreMenuFontSize.swift` is the standalone `Stepper` variant mapping `FontSize` cases to preview point sizes (7pt `.xSmall` … 61pt `.accessibility5`).
- `MoreMenuBuilder.build(withListener:model:)` hands back a `MoreMenuController: UIHostingController<MoreMenuView>` with transparent background and `preferredContentSize` passthrough, so the reader presents it as a popover.

## 3. Data flow
The reader constructs `MoreMenuModel(isWordPointerActive:state:)` describing which controls make sense for the current page type, then `MoreMenuViewModel.init(model:)` seeds each `@Published` value from singletons (`FontSizePreferences.shared.arabicFontSize/translationFontSize`, `QuranContentStatePreferences.shared.twoPagesEnabled/verticalScrollingEnabled/showLinePageDividers/showLinePageSidelines`, `WordTextPreferences.shared.wordTextType`, `ThemeService.shared.appearanceMode`, `preferences.quranMode`). Every subsequent binding change is persisted immediately in the sink (e.g. `self?.preferences.verticalScrollingEnabled = newValue`); the reader observes those same preference publishers, so the page re-renders live while the menu is open. Cross-control rules are enforced in the view model: setting `mode` to `.translation` force-disables the word pointer, and `twoPages` collapses from `.conditional` to `.alwaysOff` unless `TwoPagesUtils.hasEnoughHorizontalSpace()`. Actions needing navigation escape via the `MoreMenuListener` protocol (`onTranslationsSelectionsTapped`, `onIsWordPointerActiveUpdated`). The theme row dismisses the menu first, captures the window (`UIViewControllerReader`), then presents `ThemeSettingsController` on `deepPresentedViewController()` as a `.formSheet` with medium/large detents.

## 4. Storage & network
Purely local. All settings round-trip through the UserDefaults-backed `Core/Preferences` package and `ThemeService` (`UI/NoorUI/Sources/Theme/ThemeService.swift`), which also publishes `appearanceModePublisher` so other screens update instantly. Nothing here hits the network; translation *content* changes route out through the listener to the Translations feature instead.

## 5. Why it is built this way ON THIS PLATFORM
The `ConfigState` tri-state exists because QuranEngine is a library: a consumer embedding only the mushaf reader can hide irrelevant controls (e.g. keep `linePageDisplay` off) without forking the view — the example app simply passes a different `MoreMenuControlsState`. The theme sheet's UIKit shell is deliberate: `ThemeSettingsController.viewDidLoad()` disables `prefersScrollingExpandsWhenScrolledToEdge` with a comment explaining that UIKit otherwise adjusts the scroll view "while live theme changes are relaying out that same scroll view" — a real UISheetPresentationController/SwiftUI conflict that only appears when the sheet's own material background re-themes mid-drag. Font-size steppers align Arabic and translation labels by measuring label widths at runtime (`onSizeChange` into `arabicLabelSize/translationLabelSize`) because Arabic and Latin labels have very different natural widths.

## 6. Edge cases & offline behavior
`MoreMenuFontSize.fontIndex` force-unwraps `firstIndex(of:)` after logging an error if the stored `FontSize` isn't in the sorted set — a defensive-crash path for stale preference values. `.dropFirst()` on every sink prevents writing back the just-loaded initial value during init. Two-page layout self-hides on devices without horizontal space, and orientation controls only appear where rotation matters. Because persistence is synchronous UserDefaults writes, toggles apply even if the menu is dismissed immediately, and nothing breaks offline.
