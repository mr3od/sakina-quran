# Index tabs: suras, juz, bookmarks
> How **Quran for Android (github.com/quran/quran_android)** implements this feature. Sources read from a shallow clone @ main (2026-08-23); repo-relative paths cited throughout.

## 1. What the user sees
The home screen (`QuranActivity`) is a `ViewPager` with a custom `SlidingTabLayout` indicator and three swipeable tabs — Suras, Juz, Bookmarks (`TITLES`/`ARABIC_TITLES`). The sura tab interleaves all 114 suras under 30 juz header rows ("Juz'" + localized number) showing sura metadata; an optional translated sura name replaces the transliterated one per settings, and the "Surah" prefix is dropped in locales that override `show_surat_prefix=false` (e.g. `res/values-tr/booleans.xml`, `values-es`). A "continue reading" bookmark header/row appears at the top when a last-read position exists. The juz tab lists 240 quarter entries (8 per juz), each with a `JuzView` ring icon (juz/quarter/half/three-quarters) and overlay numbers every four entries.

## 2. Architecture & key files
`ui/QuranActivity.kt` hosts a private `PagerAdapter : FragmentPagerAdapter` (`count = 3`) returning `SuraListFragment.newInstance()`, `JuzListFragment.newInstance()`, or `BookmarksFragment.newInstance()`. For RTL locales it remaps positions via `abs(position - 2)` in both `getItem` and `getItemId` so tabs read right-to-left, swapping to `ARABIC_TITLES`. Lists render through shared pieces: `ui/helpers/QuranListAdapter`, the plain `QuranRow` model, and `QuranRowFactory`. Fragments are View-based (no Compose) and receive dependencies by field injection from `applicationComponent.inject(this)` in `onAttach`: `QuranInfo`, `QuranDisplayData`, `QuranSettings`, `ReadingBookmarksDao`, `JuzListPresenter`.

## 3. Data flow
`SuraListFragment.getSuraList()` synchronously builds the array: optional reading-bookmark header + row (offset constant `READING_BOOKMARK_ROWS = 2`), then for each juz a `QuranRow.HEADER` with `quranInfo.getStartingPageForJuz(juz)` followed by every sura whose `getPageNumberForSura(sura) < next juz start`. It live-updates via `repeatOnLifecycle(STARTED)` collecting `readingBookmarksDao.readingBookmarkFlow().distinctUntilChanged()` into `updateSuraList()` (adapter `setElements`). `onResume` re-checks `quranSettings.isShowSuraTranslatedName` (settings can change elsewhere while the fragment lives) and scrolls to `sura + juz - 1 (+ offset)` derived from `activity.latestPage()`. `JuzListFragment.fetchJuz2List()` loads quarter names either from `juzListPresenter.quarters()` (when flavor's `QuranFileConstants.FETCH_QUARTER_NAMES_FROM_DATABASE` is true) or from `R.array.quarter_prefix_array`, then emits 30 x (8+1) rows using `quranInfo.getQuarterByIndex(i)` and `getPageFromSuraAyah`; it scrolls to `(juz - 1) * 9` on resume. Taps call `QuranActivity.jumpTo(page)` / `jumpToAndHighlight(page, sura, ayah)`, which start `PagerActivity` with `"page"`, `EXTRA_HIGHLIGHT_SURA/AYAH`, and `EXTRA_JUMP_TO_TRANSLATION` taken from `settings.wasShowingTranslation`.

## 4. Storage & network
Entirely offline and download-free: structure comes from code tables behind `common/data`'s `QuranInfo`/`PageProvider` (flavor-dependent madani/warsh metadata); quarter names come from string resources or the local DB via `JuzListPresenter.quarters()`; the last-read page merges persisted `LastPage` rows with the in-memory tracker in `QuranActivity.latestPageFlow` (L97-103); bookmarks come from the SQLDelight `ReadingBookmarksDao`. No network calls exist on this screen.

## 5. Why it is built this way ON THIS PLATFORM
The index is a pure function of static mushaf geometry plus at most one dynamic row, so rebuilding a whole `Array<QuranRow>` on change is cheaper than diffing — consistent with this codebase keeping legacy MVP/View patterns in the shell while Compose stays confined to leaf feature modules. RTL is handled by position remapping rather than layout mirroring because `ViewPager` does not auto-mirror, and localized digits go through `QuranUtils.getLocalizedNumber`. Translated names are a user setting applied at build time of the list, hence the `onResume` re-check.

## 6. Edge cases & offline behavior
Both fragments install an insets listener whose comment warns that returning `WindowInsetsCompat.CONSUMED` misplaces the Snackbar under the nav bar on API <= 29, so bottom padding is applied manually. RTL devices also flip the scrollbar (`SCROLL_SCROLLBAR_POSITION_LEFT`). Scroll-position math depends on whether the reading bookmark row exists (`readingBookmarkOffset()`). `JuzListFragment` nulls its views in `onDestroyView` and guards quarter application with `isAdded`, avoiding leaks and post-detach adapter updates. If no page has been read yet (`NO_PAGE`), no auto-scroll happens.
