# Translation reading mode
> How **Quran for Android (github.com/quran/quran_android)** implements this feature. Sources read from a shallow clone @ main (2026-08-23); repo-relative paths cited throughout.

## 1. What the user sees

- **Entry point**: while reading mushaf pages in `PagerActivity`, the overflow menu (`app/src/main/res/menu/quran_menu.xml`) exposes `goto_translation` / `goto_quran` as a mutually exclusive pair whose visibility is flipped in `onPrepareOptionsMenu` (`app/src/main/java/com/quran/labs/androidquran/ui/PagerActivity.kt`). Selecting "Read translation" calls `switchToTranslation()`; if no translations are installed it launches `TranslationManagerActivity` instead (`startTranslationManager()`). Switching logs analytics via `quranEventLogger.switchToTranslationMode(translations.size)`.
- **Page transformation**: the ViewPager does not add a new screen - it *rebuilds every page* as `TranslationFragment`: a vertically scrolling, verse-by-verse view (`RecyclerView` inside `TranslationView`). The mushaf image page disappears entirely (or, on tablets, sits beside/below it - see split mode below).
- **Row composition per verse** (built in `TranslationView.setVerses`, `app/src/main/java/com/quran/labs/androidquran/ui/translation/TranslationView.java`):
  - Sura header band when entering a new sura;
  - A standalone basmalah row at ayah 1 of every sura except 1 and 9;
  - A verse-number badge (`AyahNumberView`, localized "sura:ayah");
  - Optional Arabic uthmani text of the verse *before* the translation (setting "Show ayah in Arabic above the translation", default on), rendered with the mushaf typeface at 1.4x the Arabic size setting (`ARABIC_MULTIPLIER`);
  - A translator-name row shown only when more than one translation is active;
  - One text row per active translation, then a divider/spacer closing the verse block.
- **Expandable content inside text rows** (`TranslationAdapter.onBindViewHolder`):
  - Long tafaseer are truncated at 750 characters (`MAX_TAFSEER_LENGTH`) and end with a clickable "المزيد…" ("more") span backed by `ExpandTafseerSpan`; tapping expands the full text in place (`expandedTafseerAyahs` set + `notifyItemChanged`).
  - Footnotes encoded `[[like this]]` are replaced by small superscript numbers (`TranslationFootnoteHelper.footnoteCognizantText`); tapping a number (`ExpandFootnoteSpan`) expands that footnote inline in smaller colored text; expanded footnote numbers live in `expandedFootnotes`.
  - Quoted Quran fragments inside tafseer («…» / ﴿…﴾ / {…}) are tinted via regex-detected `IntRange`s.
  - Cross-referenced tafseer entries collapse to the string *"This ayah's tafseer is included with the tafseer of ayah %d (Click to expand)"* (`R.string.see_tafseer_of_verse`); tapping smooth-scrolls if the target is on the same page, otherwise jumps to another page via a new `PagerActivity` intent carrying `EXTRA_HIGHLIGHT_SURA/AYAH` (`TranslationView.onJumpToAyah`).
- **Verse interaction**: tapping empty space toggles the action bar; long-pressing a verse (or clicking another verse while one is selected) selects it, paints `ayahSelectionColor` behind its rows, and floats the standard ayah toolbar anchored to the verse-number box (`TranslationAdapter.getSelectedVersePopupPosition` -> `SelectionIndicator.SelectedPointPosition`). From there the usual panels (bookmark, share, play from here, tafseer) open.
- **Follow-along highlighting**: during audio playback the current verse is highlighted (`HighlightTypes.AUDIO`) and auto-scrolled to with a 64px offset.
- **Action bar becomes a spinner**: in translation mode the title is replaced by `TranslationsSpinnerAdapter` listing installed translations as checkboxes; changing the set writes `QuranSettings.activeTranslations` and calls `refresh()` on adjacent fragments (`translationItemChangedListener` in `PagerActivity.kt`).
- **Exposed settings** (`app/src/main/res/xml/quran_preferences.xml`, "Translation" category): Translation manager entry; "Show ayah in Arabic above the translation" checkbox (`prefs_ayah_before_translation`, default true); "Display translations in dyslexia friendly font" (`prefs_use_dyslexic_font`, default false, ships `OpenDyslexic.otf` asset); two size seekbars - Arabic text size and translation text size (default 15, max 40). A dual-screen category offers "split page and translation" (`prefs_split_page_and_translation`), which renders mushaf image + translation simultaneously in `TabletFragment.Mode.SPLIT`.
- **Fonts**: Arabic rows always use the flavor-specific mushaf face (`TypefaceManager.getUthmaniTypeface` - `uthmanic_hafs_ver12.otf`, `noorehira.ttf`, warsh/qaloon variants per `QuranFileConstants.FONT_TYPE`); Arabic-language tafseer rows use `kitab.ttf`; LTR rows may use OpenDyslexic. So "adjustable fonts" means size controls plus one accessibility font, not arbitrary font picking.
- **Night mode**: `TranslationAdapter.refresh()` derives text color from `nightModeTextBrightness` blended with a log-scaled background brightness (`50 * ln1p(backgroundBrightness) + original`, capped at 255) so text never turns invisible against the darkened page background.

## 2. Architecture & key files

- `app/src/main/java/com/quran/labs/androidquran/ui/PagerActivity.kt` -> owns reading mode (`showingTranslation`, `switchToTranslation()/switchToQuran()`, `setTranslationMode()/setQuranMode()` on the pager adapter), the translations spinner, and the "download required files" prompt when the Arabic database is missing.
- `app/src/main/java/com/quran/labs/androidquran/ui/helpers/QuranPageAdapter.kt` (`QuranPageAdapter`) -> `PageMode` (`SingleTranslationPage` / `SingleArabicPage` / dual-screen `Mix|Translation|Arabic`) decides what `getItem(position)` inflates: `TranslationFragment`, `QuranPageFragment`, or `TabletFragment`. `getItemPosition` returns `POSITION_NONE` so a mode flip tears down and rebuilds all fragments. A `PageViewFactory` parameter is the seam used by alternate page types such as `:feature:linebyline`.
- `app/src/main/java/com/quran/labs/androidquran/ui/fragment/TranslationFragment.kt` -> one translated page. Injected through the per-page Metro scope: `(activity as? PagerActivity)?.pagerActivityComponent?.quranPageComponentFactory()?.generate(pages)?.inject(this)`; implements `QuranPage` + `PageController` + `AyahInteractionHandler`, delegates highlight/audio events to `AyahTrackerPresenter` and data loading to `TranslationPresenter`.
- `app/src/main/java/com/quran/labs/androidquran/view/QuranTranslationPageLayout.java` -> `QuranPageLayout` subclass that swaps the image content for a `TranslationView`, opts out of the ScrollView wrapper (`shouldWrapWithScrollView() == false`, the RecyclerView scrolls itself), and paints the night-mode background.
- `app/src/main/java/com/quran/labs/androidquran/ui/translation/TranslationView.java` -> FrameLayout hosting the `LinearLayoutManager` RecyclerView; converts `List<QuranAyahInfo>` into `TranslationViewRow`s; owns selection state; computes toolbar anchor positions; applies display-cutout insets via Insetter + `SpacerDecoration` (`ui/translation/SpacerDecoration.kt`).
- `app/src/main/java/com/quran/labs/androidquran/ui/translation/TranslationAdapter.kt` -> the renderer. Row types map to layouts (`quran_translation_header_row`, `quran_translation_arabic_row`, `quran_translation_verse_number_row`, `quran_translation_translator_row`, `quran_translation_text_row`, `quran_translation_spacer_row`); holds expansion state, highlight bookkeeping (start/count + merged `notifyItemRangeChanged(..., HIGHLIGHT_CHANGE)` payload binds), fonts/colors refreshed from settings.
- `app/src/main/java/com/quran/labs/androidquran/ui/translation/TranslationViewRow.kt` -> immutable row model (`@IntDef` types BASMALLAH/SURA_HEADER/QURAN_TEXT/TRANSLATOR/TRANSLATION_TEXT/VERSE_NUMBER/SPACER) plus `footnoteCognizantText` delegation.
- `app/src/main/java/com/quran/labs/androidquran/ui/helpers/ExpandTafseerSpan.kt`, `ExpandFootnoteSpan.kt` -> thin `ClickableSpan`s carrying a `(View)` / `(View, Int)` callback up to the adapter.
- `app/src/main/java/com/quran/labs/androidquran/ui/helpers/TranslationFootnoteHelper.kt` -> pure function that folds footnote ranges (sorted descending, so earlier indices stay valid while replacing) into either superscript markers or expanded styled text.
- `app/src/main/java/com/quran/labs/androidquran/presenter/translation/BaseTranslationPresenter.kt` -> the reusable engine (shared with `InlineTranslationPresenter` for the bottom-sheet verse panel): `getVerses()`, `combineAyahData()`, `ensureProperTranslations()`, filename->`LocalTranslation` cache kept fresh by subscribing to `TranslationListPresenter.translations()` in its constructor.
- `app/src/main/java/com/quran/labs/androidquran/presenter/translation/TranslationPresenter.kt` -> `@QuranPageScope` subclass bound to `TranslationScreen` (`setVerses(page, translations, verses)` + `updateScrollPosition()`); `refresh()` maps each page through `quranInfo.getVerseRangeForPage(it)`.
- `app/src/main/java/com/quran/labs/androidquran/model/translation/TranslationModel.kt|TranslationModelImpl.kt` -> repository seam over verse databases; Arabic comes from `QuranDataProvider.QURAN_ARABIC_DATABASE` unmapped, translations go through `ayahMapper.mapRange/mapKufiData` (handles differing ayah numbering between mushaf types).
- `app/src/main/java/com/quran/labs/androidquran/database/TranslationsDBAdapter.kt|TranslationsDBAdapterImpl.kt` + `common/translation/src/main/kotlin/com/quran/mobile/translation/data/TranslationsDataSource.kt` -> reactive SQLDelight catalog of installed translations (filtered by `quranFileUtils.hasTranslation(filename)` so rows without a downloaded file disappear).
- `app/src/main/java/com/quran/labs/androidquran/util/TranslationUtil.kt` -> text-markup parser: `[[...]]` footnotes, `[«{﴿]...[﴾}»]` inline ayat, short purely-numeric text treated as a hyperlink ayah id; `MINIMUM_PROCESSING_VERSION = 5` gates which databases contain parseable markup.
- `app/src/main/java/com/quran/labs/androidquran/presenter/translation/TranslationManagerPresenter.kt` + `ui/TranslationManagerActivity.kt` -> catalog fetch/cache/reconcile and download orchestration.
- `app/src/main/java/com/quran/labs/androidquran/ui/util/TypefaceManager.kt`, `ui/helpers/UthmaniSpan.kt` -> cached `Typeface` singletons for mushaf/tafseer/dyslexic faces.

Seams worth noting: the `TranslationModel` interface (data source abstraction), `TranslationsDBAdapter` (catalog), `BaseTranslationPresenter<T>.TranslationScreen`-style view contracts, the `AyahTrackerItem` polymorphism (`AyahTranslationTrackerItem` vs `AyahImageTrackerItem`) that lets one `AyahTrackerPresenter` drive both image and text pages, and the Metro `@QuranPageScope` component factory that scopes one presenter set per page.

## 3. Data flow

1. **User taps "Read translation"** -> `PagerActivity.onOptionsItemSelected` (`R.id.goto_translation`) -> `switchToTranslation()`: ends any ayah selection, `pagerAdapter.setTranslationMode()`, sets `showingTranslation`, invalidates options menu, swaps title for spinner. If `translations` is empty it diverts to `TranslationManagerActivity`.
2. **Fragment construction** -> `QuranPageAdapter.getItem()` returns `TranslationFragment.newInstance(page)`; `onAttach` pulls page-scoped dependencies out of the Metro graph; `onCreateView` builds `QuranTranslationPageLayout` programmatically (no XML inflation for the page body).
3. **Load** -> `onResume` binds `presenter.bind(this)` and `updateView()` -> layout restyles from `QuranSettings` -> `refresh()` launches `TranslationPresenter.refresh()` on a fragment-owned `MainScope` coroutine.
4. **Query** -> `BaseTranslationPresenter.getVerses(getArabic = wantArabicInTranslationView(), translationsFileNames = quranSettings.activeTranslations, verseRange)` runs inside `withContext(Dispatchers.IO)`: reads the catalog (`translationsAdapter.getTranslations().first()`), sorts by `displayOrder`, filters to requested filenames, **falls back to all installed translations when the resulting list is empty** (all unchecked, or checked ones uninstalled), then fans out one `async` job per translation (`SupervisorJob` scope) plus one for Arabic.
5. **Data sources** -> each job calls `TranslationModelImpl.getTranslationFromDatabase(range, filename)` -> `DatabaseHandler.getDatabaseHandler(context, filename, quranFileUtils)` (static per-file cache) -> raw SQLite `verses(sura, ayah, text)` query; `ensureProperTranslations` inserts blank `QuranText` placeholders where a database is missing records (comment cites ibn Kathir missing 3 records in suras 5, 17, 87).
6. **Merge & parse** -> `combineAyahData` zips the parallel lists into `List<QuranAyahInfo>`; per translation, if `minimumVersion >= 5` the raw string goes through `TranslationUtil.parseTranslationText` producing `TranslationMetadata(text, link, linkPage, ayat ranges, footnotes)`, else it is passed through verbatim; failed awaits become empty lists so one bad database cannot blank the page.
7. **Render** -> result returns to the main thread; `screen.setVerses(...)` -> `TranslationFragment.setVerses` -> `TranslationView.setVerses` flattens verses into `TranslationViewRow`s -> `adapter.setData(rows)` (clearing expansion state) -> `notifyDataSetChanged()`; then `updateScrollPosition()` restores the saved `findFirstCompletelyVisibleItemPosition()`.
8. **Interaction loop** -> row click: if a selection exists and a different verse was clicked, treat as new selection (`handleClick` -> `onVerseSelected`), else toggle action bar. Long press: `selectVerseRows` -> `TranslationView.onVerseSelected` -> `pageController.handleLongPress(SuraAyah)` -> `TranslationFragment.handleLongPress` publishes `ReadingEventPresenter.onAyahSelection(AyahSelection.Ayah(suraAyah, toolbarPosition))` -> `AyahTrackerPresenter` reacts (highlight, slide-up panels). Scroll: `onScrollChanged` republishes the selection with a fresh toolbar coordinate; `TranslationView.updateAyahToolBarPosition` hides the menu if the verse scrolled off-screen (and deliberately never mutates the RecyclerView from inside `onScrolled`).
9. **External events** -> audio position updates arrive through `ReadingEventPresenter`/`AudioStatusRepository` into `AyahTrackerPresenter` -> `AyahTranslationTrackerItem.onHighlightAyah` -> `TranslationView.highlightAyah` -> `adapter.highlightAyah` (merged range notifications, forced scroll for AUDIO). Settings changes (font size, night mode, active translations) re-enter via `updateView()`/`refresh()`.

## 4. Storage & network

- **Catalog database** `translations.db` (SQLDelight, `AndroidSqliteDriver`, created in `common/translation/.../di/TranslationDataModule.kt`): table `translations(id INTEGER PRIMARY KEY, name TEXT NOT NULL, translator TEXT, translatorForeign TEXT, filename TEXT NOT NULL, url TEXT NOT NULL, languageCode TEXT, version INTEGER DEFAULT 0, minimumRequiredVersion INTEGER DEFAULT 0, userDisplayOrder INTEGER DEFAULT -1)`. Queries: `all`, `update` (REPLACE), `greatestDisplayOrder`, `deleteById`, `deleteByFileName` (`common/translation/src/main/sqldelight/com/quran/mobile/translation/translations.sq`). Migrations `1.sqm`–`4.sqm` are build-time verified against committed schema snapshots (`src/main/sqldelight/.../databases/*.db`).
- **Verse databases**: one SQLite file per downloaded translation inside `quranFileUtils.getQuranDatabaseDirectory()`, opened lazily by `DatabaseHandler` (static map cache; `clearDatabaseHandlerIfExists(fileName)` closes the handler when the underlying file is replaced). Expected tables: `verses(sura, ayah, text[, extraData])` and a `properties` table holding schema/text versions read by `getSchemaVersion()/getTextVersion()`. Arabic script comes from the separate bundled-by-download `QURAN_ARABIC_DATABASE`.
- **Preferences** (SharedPreferences behind `QuranSettings`, keys in `data/Constants.kt`): `ayahBeforeTranslation` (bool, default true), `useDyslexicFont` (bool, default false), `ayahTextSize` / `translationTextSize` (int, default 15), `activeTranslations` (string set of filenames), `wasShowingTranslation` (mode restore across launches), `lastTranslationsUpdate` + `MIN_TRANSLATION_REFRESH_TIME` (1h catalog cache TTL), `haveUpdatedTranslations` (drives "updates available" affordance).
- **Network**:
  - Catalog JSON: `Constants.HOST + "data/translations.php?v=5"` fetched with the shared OkHttp client, parsed by Moshi (`dao/translation/TranslationList`), cached on disk as `translations.v5.cache` beside the databases. `TranslationManagerPresenter.checkForUpdates()` refreshes only when older than 1 hour; `getTranslations(forceDownload=false)` merges cached + remote flows (`take(1)` when cache is fresh).
  - Reconciliation: `mergeWithServerTranslations` compares server rows with local DB rows and on-disk files — deletes files whose recorded version mismatches (treated as corrupted), removes stale DB rows for schema-v5+ replacements (same filename, new id), backfills missing `languageCode` on old rows.
  - Binary download: `downloadItem` in `TranslationManagerActivity` renames an existing file to `fileName + UPGRADING_EXTENSION`, then starts `service/QuranDownloadService` with `DOWNLOAD_TYPE_TRANSLATION`, output filename (`.zip` appended when the URL ends in zip) and a `DefaultDownloadReceiver` listening on `QuranDownloadNotifier.ProgressIntent.INTENT_NAME`. On success the backup is deleted, `displayOrder` is assigned `max+1`, and the filename joins `activeTranslations`; on failure the backup is restored/removed.
- **Caching/invalidation summary**: verse text is fully local (offline-first) — nothing on the reading path touches the network; only the catalog has a TTL-based cache, invalidated hourly or by pull-to-refresh; the SQLDelight `all` query is observed as a Flow so installs/removals propagate to open pages automatically.

## 5. Why it is built this way ON THIS PLATFORM

- **Images-first app, text as an alternate page type**: the mushaf is shipped as pre-rendered page images bucketed by device width, so "correct" Quran rendering is solved by bitmaps; translation mode must coexist with that inside the same `ViewPager`. Rather than fork the reading experience, the feature plugs into the existing `PageController`/`AyahTracker` contracts — `AyahTranslationTrackerItem` answers the same queries (`getToolBarPosition`, `getQuranAyahInfo`, `getLocalTranslations`) that the image tracker answers from glyph-coordinate databases. That is why selection toolbars, audio follow-highlight, bookmarks and sharing work identically in both modes.
- **RecyclerView, not ScrollView+TextView**: a single madani page can span dozens of verses times N active translations with multi-thousand-character tafseer entries; recycling plus row-typed view holders bounds memory on low-end devices, and payload-based partial rebinding (`HIGHLIGHT_CHANGE`) makes highlight flicker-free without rebinding text.
- **Spans instead of child views** for footnotes/expansion/hyperlinks: one `TextView` per row keeps the view hierarchy shallow, and expand/collapse is a cheap `notifyItemChanged(position)` with state held in adapter-side sets/maps — surviving recycling without touching the data model.
- **Databases downloaded on demand, not assets in the APK**: translations total hundreds of MB across ~100 entries; shipping them would balloon the APK and violate Play's expectations. Per-file SQLite also decouples data versions (`minimumRequiredVersion`) from app releases, letting the parser gate on `version >= 5` before trusting markup.
- **Foreground-service-mediated downloads**: `QuranDownloadService` exists because large downloads must survive app backgrounding (Doze/network restrictions), with retry/resume, Wi-Fi locks and progress notifications; the activity only listens via `LocalBroadcastManager`.
- **Fragment teardown on mode switch** (`POSITION_NONE`) is deliberate: image pages and translation pages share nothing visually, so rebuilding is simpler than mutating, and the only expensive state (scroll offset) is carried through `onSaveInstanceState`.
- **Manual inset handling**: the RecyclerView runs edge-to-edge, so display-cutout insets are converted to item decorations (`SpacerDecoration`) instead of padding, keeping content clear of notches in landscape/foldable postures.
- **A web/mobile-cross-platform implementation would differ**: streaming text from an API with a local cache instead of shipping monolithic SQLite downloads, using system dynamic-type/RTL text stacks instead of hand-managed typefaces and per-row directionality heuristics, and declarative lists where footnote expansion is state in a view model rather than mutable span bookkeeping. Here those choices are driven by offline-first expectations (users in low-connectivity regions), the desire to keep Arabic typography pixel-faithful, and the legacy View toolkit the rest of the reader is built on.

## 6. Edge cases & offline behavior

- **No/empty translation selection**: if `activeTranslations` names nothing usable (all unchecked, or checked-but-deleted files), `BaseTranslationPresenter.getVerses` silently enables all installed translations rather than showing a blank page. Rows whose translation text came back empty are still emitted as `""` so per-verse column alignment across translations holds.
- **Bad data tolerance**: `ensureProperTranslations` pads missing verse records (documented ibn Kathir gaps); individual `async` results are awaited inside try/catch — a corrupt or locked database degrades that translation to empty instead of failing the page; Arabic load failure is tolerated independently of translation failures.
- **Corrupt/interrupted downloads**: catalog reconciliation deletes local files whose version doesn't match expectations; the upgrade flow renames the old file to `*.upgrade` first and `handleDownloadFailure` restores it, so a failed download never leaves the user worse off than before. `DatabaseHandler.validDatabase()` guards opening, and `clearDatabaseHandlerIfExists` prevents stale handles to replaced files.
- **Cross-page tafseer links**: if the linked verse isn't on the current page, `onJumpToAyah` starts a fresh `PagerActivity` with highlight extras; same-page targets merely `smoothScrollToPosition`.
- **RTL/locale**: directionality is decided per row via `SearchTextUtil.isRtl(text)`; Arabic tafseer additionally gets the `kitab.ttf` face, but other RTL languages deliberately fall back to the system font ("the Arabic font isn't compatible with other RTL languages that share some Arabic characters"). Footnote numbers use `QuranUtils.getLocalizedNumber` for locale-aware digits. LTR rows honor the dyslexic-font preference.
- **Basmalah handling**: rendered as its own row for ayah 1 of every sura except 1 and 9, and stripped from the ayah text itself by `ArabicDatabaseUtils.getAyahWithoutBasmallah` to avoid duplication.
- **Night mode readability**: brightness blending capped at 255; header/footer/divider colors come from dedicated night resources; `QuranTranslationPageLayout.updateBackground` repaints the page background independently of the global theme.
- **State restoration**: scroll position survives configuration changes and process death (`SI_SCROLL_POSITION`, applied only after data arrives via `updateScrollPosition()`); reading mode itself persists through `wasShowingTranslation` in `PagerActivity`'s saved state; expansion state (open tafseer/footnotes) intentionally resets on data reload.
- **First-run vs upgrade**: first switch to translation mode with zero downloads routes to the manager; separately, `switchToTranslation` prompts for the extra Arabic search database when `!quranFileUtils.hasArabicSearchDatabase()` (needed for the Arabic-before-translation text and Arabic search). Older catalogs lacking `languageCode` are patched on the next sync.
- **Accessibility**: footnote/expansion spans sit behind `LinkMovementMethod` (activatable by keyboard/accessibility services) and verse badges are discrete views, but this View-stack page has no explicit content descriptions or semantics — a gap relative to the newer Compose leaf modules in the repo.
- **Architecture note vs. prior assumptions**: this path is now coroutine/Flow based (`MainScope`, `Dispatchers.IO`, SQLDelight `asFlow().mapToList()`), not RxJava3; Rx remains only in peripheral screens (e.g. `TranslationManagerActivity` click subscriptions).
