# Night mode and app themes
> How **Quran for Android (github.com/quran/quran_android)** implements this feature. Sources read from a shallow clone @ main (2026-08-23); repo-relative paths cited throughout.

## 1. What the user sees
Two independent controls. Under Display settings, an "Appearance" list preference offers Light / Dark / Default(follow system) for the app chrome — toolbars, lists, settings screens. Separately, a "Night Mode" checkbox darkens only the *reading* surfaces: mushaf page images are inverted to white-text-on-dark, translation views switch to a dark palette, and two sliders appear (dependent on the checkbox) — text brightness (0–255, default 255) and background brightness (0–64, default 0) — letting readers tune how stark the inverted page looks.

## 2. Architecture & key files
- `app/src/main/res/xml/quran_preferences.xml` — `prefs_night_mode` CheckBox (:64), `SeekBarTextBrightnessPreference` with `android:max="255"` default 255 (:70), `SeekBarBackgroundBrightnessPreference` with `android:max="64"` default 0 (:79); both carry `android:dependency="@string/prefs_night_mode"`. The theme `ListPreference` (`prefs_app_theme`, entries `@array/themes`) sits at :21.
- `app/.../util/ThemeUtil.kt` — the entire app-theme layer: maps `"light"/"dark"/"default"` (Constants.THEME_*) to `AppCompatDelegate.MODE_NIGHT_NO/YES/FOLLOW_SYSTEM` and calls `setDefaultNightMode`.
- `app/.../ui/preference/SeekBarTextBrightnessPreference.kt`, `SeekBarBackgroundBrightnessPreference.kt`, and base `SeekBarPreference.kt` — slider widgets persisting `PREF_NIGHT_MODE_TEXT_BRIGHTNESS` / `PREF_NIGHT_MODE_BACKGROUND_BRIGHTNESS`.
- `app/.../view/HighlightingImageView.java` — where the actual pixel work happens.
- Consumers applying the palette per surface: `view/QuranPageLayout.java`, `QuranImagePageLayout.kt`, `QuranTranslationPageLayout.java`, `QuranPageWrapperLayout.java`, `view/AyahNumberView.java`, `ui/translation/TranslationAdapter.kt`.

## 3. Data flow
Toggling night mode writes the boolean through `QuranSettings.isNightMode()` (QuranSettings.java :72), which every layout queries when it inflates/refreshes; `PagerActivity` then refreshes fragments so backgrounds and color filters update without recreating the pager. In `HighlightingImageView.adjustNightMode()`, changing either slider triggers recomputation (:208): `nightModeTextBrightness = min(255, 50 * log1p(backgroundBrightness) + textBrightness)` — raising background brightness automatically lifts text brightness so contrast never collapses toward gray-on-gray — then invalidates the color filter. On draw (:365), if night mode is on and no filter is applied, a `ColorMatrixColorFilter` with matrix `-1,0,0,0,brightness / 0,-1,0,0,brightness / 0,0,-1,0,brightness / 0,0,0,1,0` inverts the bitmap while offsetting each channel by the computed brightness; otherwise the filter is cleared. Overlay text (page number/sura header) is drawn in `Color.rgb(nightModeTextBrightness ×3)` (:461).

## 4. Storage & network
Everything is local SharedPreferences via `SettingsImpl`; defaults live in `data/Constants.kt` (:11-12: `DEFAULT_NIGHT_MODE_TEXT_BRIGHTNESS = 255`, `DEFAULT_NIGHT_MODE_BACKGROUND_BRIGHTNESS = 0`). The theme value likewise persists as a string under `Constants.PREF_APP_THEME` ("appTheme") and is re-applied on process start by calling `ThemeUtil.setTheme`. No network involvement whatsoever — night mode operates on already-downloaded bitmaps at draw time rather than swapping image assets.

## 5. Why it is built this way ON THIS PLATFORM
The mushaf is a scanned image, so Android's standard DayNight resource qualifiers cannot darken it; inversion has to be a runtime pixel operation on the `ImageView`, which is exactly what the negative ColorMatrix does cheaply on the GPU-backed render path without keeping a second copy of every page bitmap. Keeping night mode separate from `AppCompatDelegate` themes is deliberate: a user can read inverted pages inside a light-chrome app or vice versa, since the two control disjoint view trees (image/reading surfaces vs. framework widgets). The log1p coupling of the two sliders exists because pure inversion of cream-colored mushaf paper yields harsh results on OLED panels — the background slider raises the black floor, and the formula compensates text brightness so glyphs stay legible. The background slider is capped at 64 (not 255) precisely because it should tint, not whiten, the page.

## 6. Edge cases & offline behavior
Because filtering happens at draw time, it works identically on cached images, images still downloading (placeholder surfaces), and custom page types that ultimately show bitmaps. The `isNightMode && !isColorFilterOn` guard (:365) prevents stacking filters across repeated invalidations, and any settings change resets `isColorFilterOn` to force re-application. Highlight rectangles and ayah-selection overlays must remain visible after inversion; overlay colors are recomputed from the same brightness scalar (`initOverlayParamsColor`). Translation text colors follow the same sliders through `TranslationAdapter`, so mixed image+text screens stay consistent. Fully offline: no asset swap, no download, and reverting to day mode instantly restores original bitmaps by clearing the filter.
