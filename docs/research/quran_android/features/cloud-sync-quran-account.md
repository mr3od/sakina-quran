# Cloud sync with Quran.com account
> How **Quran for Android (github.com/quran/quran_android)** implements this feature. Sources read from a shallow clone @ main (2026-08-23); repo-relative paths cited throughout.

## 1. What the user sees

**Settings — "Account" category (top of the list).** `feature/sync` contributes a preference category via `QuranSyncSettingsPreferenceProvider.addPreferences()` (`feature/sync/src/main/kotlin/com/quran/mobile/feature/sync/QuranSyncSettingsPreferenceProvider.kt`). It is inserted with `order = -1` so it sorts above every XML-defined category, titled `quran_sync_settings_category` ("Account"). The single row inside is an `AccountPreference` (`AccountPreference.kt`) — a plain androidx.preference `Preference` whose layout root is a `ComposeView` (`res/layout/quran_sync_account_preference.xml`) rendering `AccountSettingsRow`, so the row re-renders itself from `syncManager.authState` without a manual rebuild on fragment resume:
- **Signed out:** a rounded `primaryContainer` card ("Sign in to sync" / summary "Bookmarks, collections & notes") with a person avatar circle and chevron; tapping launches `QuranSyncActivity`.
- **Signed in:** avatar circle with the first letter of display name/email (`accountInitial()`), email or name as title with subtitle "Synced", chevron; below a divider an inline red "Log out" row that calls `syncManager.signOut()` directly — sign-out needs no sub-page.

**Sign-in screen.** `QuranSyncActivity` (not exported, `singleTop`, edge-to-edge) hosts `QuranSyncScreen` (Compose Material 3). Content is driven purely by the four `AuthState` variants from the shared library:
- `Idle`/`Error` → hero layout: circular sync icon, headline "Sync your Quran everywhere", subtitle "Sign in to keep your progress backed up and available on every device", three check-marked benefit rows (bookmarks across devices, custom collections, verse notes), full-width "Log in" button (spinner replaces label while the flow runs), caption "You'll continue with Quran.com", and an inline error line.
- `Loading` → spinner + "Signing in".
- `Success` → "Signed in" plus label/value rows for Name, Email and Account ID taken from `UserInfo`, and an outlined "Log out" button.

**Bookmarks screen CTA card.** `BookmarksFragment.onCreateView()` sets a `ComposeView` at `R.id.sync_sign_in_card` (in `app/src/main/res/layout/quran_bookmarks_list.xml`) to `BookmarksSignInCard` (`SyncSignInCard.kt`): "Sync your bookmarks everywhere" / "Access them on any device, any time" with a "Sign in with Quran.com" button and an X dismiss icon. The card renders nothing when sync isn't configured, the user is signed in, or it was dismissed before (dismissal persisted).

**Manual sync gesture.** The bookmarks list's `SwipeRefreshLayout` pull-to-refresh is enabled only while signed in (`canTriggerSyncFlow` collected in `repeatOnLifecycle(STARTED)`); pulling calls `syncManager.triggerSync()`.

**Unconfigured builds see nothing.** All of the above is gated on `QuranSyncManager.isConfigured`; if the OAuth client id resource is blank (any build without the private `oauth.properties`, e.g. a stock open-source build), no settings row is added, `QuranSyncActivity.finish()`es immediately in `onCreate`, the CTA card renders nothing, and pull-to-refresh stays disabled.

## 2. Architecture & key files

Feature module `:feature:sync` (namespace `com.quran.mobile.feature.sync`; depends on `:common:bookmark`, `:common:data`, `:common:di`, `:common/ui/core`, Compose, and one external artifact `com.quran:mobile-sync:0.1.18` = the Kotlin-multiplatform `com.quran.shared.auth/.persistence/.pipeline` graphs, per `gradle/libs.versions.toml`):

- `feature/sync/.../QuranSyncManager.kt` — `@SingleIn(AppScope)` singleton owning (a) the shared multiplatform graph via `SharedDependencyGraph.init(driverFactory, storage = createMobileSyncStorage(context), environment, authConfig)`, built eagerly in all states (configured/unconfigured/logged-in/out); (b) Android OIDC plumbing: `AndroidCodeAuthFlowFactory(useWebView = false)`, per-activity registration tokens (`registerAuthActivity`/`unregisterAuthActivity`), an `InactiveAuthFlowFactory` that throws if login is attempted with no foreground activity; (c) public API: `authState: StateFlow<AuthState>`, `canTriggerSync(Flow)`, `showBookmarksSignInCardFlow`, `login()`, `logout()`, `signOut()`, `triggerSync()`, `dismissBookmarksSignInCard()`; (d) crash-recovery state for interrupted logouts.
- `feature/sync/.../QuranSyncConfig.kt` — reads build-injected string resources (`quran_sync_oauth_client_id`, `_issuer_url`, `_redirect_scheme`, `_environment`); builds `redirectUri = "<scheme>://callback"`; derives `AppEnvironment.PRODUCTION/PRELIVE` from the environment string or issuer URL substrings (`prelive/preprod/staging/stage/dev` vs `prod`); `isConfigured = clientId.isNotBlank()`.
- `feature/sync/.../QuranSyncActivity.kt` + `di/QuranSyncComponent.kt` — Activity-scoped Metro `@GraphExtension(ActivityLevelScope)` component injecting `QuranSyncManager`; registers the auth activity, unregisters in `onDestroy`.
- `feature/sync/.../QuranSyncScreen.kt`, `AccountSettingsRow.kt`, `AccountPreference.kt`, `SyncSignInCard.kt` — Compose UI layer (state rendering only; no view model — the manager *is* the state holder).
- `feature/sync/.../QuranSyncRepositoryProvider.kt` — `@ContributesBinding` implementation of the seam below: six thin adapters (`SyncBookmarksRepository`, `SyncBookmarkCollectionsState`, `SyncCollectionsRepository`, `SyncCollectionBookmarksRepository`, `SyncReadingBookmarksRepository`, `SyncReadingSessionsRepository`) delegating to `graph.quranDataService`.

Seams (the reason :app compiles without knowing about sync internals):

- `common/bookmark/src/main/java/com/quran/mobile/bookmark/di/MobileSyncRepositoryProvider.kt` — interface exposing shared-library repository types; `common/bookmark/di/BookmarkDataModule.kt` provides each of them *from* this provider, so every DAO impl in `common/bookmark/model/*` is silently backed by the sync pipeline.
- `com.quran.mobile.di.ExtraPreferencesProvider` — the settings-row injection point consumed by `app/.../ui/fragment/QuranSettingsFragment.kt` (`Set<ExtraPreferencesProvider>`).
- `common/bookmark/model/{BookmarksDaoImpl,ReadingBookmarksDaoImpl,RecentPagesDaoImpl}.kt` — app-facing DAOs (`com.quran.data.dao.*`) rewritten on top of the shared repositories, including page-coordinate mapping (`ReadingBookmarkPageMapper`) between canonical storage pages and the current mushaf page type, and local timestamp stamping via `time/MobileSyncTimestampProvider.kt` (kotlin.time `Clock.System.now()` → `PlatformDateTime`).
- `common/bookmark/importdata/MobileSyncImporter.kt` — wraps the shared `PersistenceImportRepositoryImpl` for bulk imports; `common/bookmark/migration/LegacyBookmarksDataSource.kt` + `LegacyBookmarkMigrationNormalizer.kt` define the legacy→sync snapshot contract.

App-module glue:

- `app/src/main/java/com/quran/labs/androidquran/model/bookmark/LegacyBookmarksMigrator.kt` (+ `model/bookmark/LegacyBookmarksDataSource.kt`, reading through the legacy `database/BookmarksDBAdapter`) — one-shot migration guarded by a settings flag.
- `app/.../presenter/data/QuranDataPresenter.kt` — chains `migrateLegacyBookmarks()` ahead of the startup page-check Completable.
- `app/.../ui/fragment/BookmarksFragment.kt` — injects `QuranSyncManager` directly for the card and pull-to-refresh.
- `app/build.gradle.kts` (`androidComponents.onVariants`, lines ~124–195) — injects the four sync string resources as variant `ResValue`s from `oauth.properties` (gitignored), resolved with suffix precedence applicationId → variant → flavor → bare key (`syncProperty()`); also emits `oidcRedirectScheme`/`oidcRedirectHost` manifest placeholders kept "aligned with QuranSyncConfig.redirectUri".

## 3. Data flow

**Sign-in (UI event → effect):**
1. Settings row tap → `Intent(QuranSyncActivity)` → `onCreate` resolves Metro graph via `(application as QuranApplicationComponentProvider)... as? QuranSyncComponentInterface`, then `syncManager.registerAuthActivity(this)`: lazily creates `AndroidCodeAuthFlowFactory(useWebView = false)`, stores a monotonic registration id, and pushes the factory into the shared library's static `AuthFlowFactoryProvider`. Returns `null` (no-op) when unconfigured or when the activity already is OIDC's own `HandleRedirectActivity`.
2. Screen shows `SignedOutContent`; "Log in" → `scope.launch { syncManager.login() }` with local `isActionRunning`/`actionError` state.
3. `login()` wraps work in `runAuthAction`: an `async` on `authActionScope` (`SupervisorJob() + Dispatchers.Main.immediate`, app-scoped so Activity recreation cannot cancel the pending browser redirect) serialized by `authActionMutex` with an `activeAuthActions` counter.
4. Inside: `graph.authService.loginWithReauthentication()` — OIDC authorization-code flow against the configured issuer, opened in a browser/custom tab (not a WebView), redirect captured back through the registered activity; `clientSecret = null`, i.e. a public client. Re-authentication is forced so a stale quran.com browser session is never silently reused after logout.
5. On token exchange the shared lib persists tokens (`AndroidSettingsTokenStore`, SharedPreferences-backed) and `authState` flips `Idle → Loading → Success(userInfo)`; `QuranSyncManager.login()` then calls `graph.quranDataService.triggerSync()` for an initial pull/push.
6. UI recomposes to `SignedInContent(userInfo)` from the same `StateFlow`.

**Data writes (reading position example):** page change in `PagerActivity` → `feature/reading/presenter/ReadingBookmarkPresenter` → `readingBookmarksDao.setPageReadingBookmark(page)` (`app/.../ReadingBookmarkPresenter.kt` line 113 launches into `AppCoroutineScope`) → `common/bookmark/model/ReadingBookmarksDaoImpl.setPageReadingBookmark()` maps UI page → canonical storage page and stamps `timestampProvider.now()` → `readingBookmarksRepository.addPageReadingBookmark(page, timestamp)` (a `SyncReadingBookmarksRepository` adapter) → `QuranDataService` in mobile-sync writes the row locally and reconciles with quran.com when authenticated. Reads return as cold Flows combined with `pageMapper.pageTypeFlow()` so stored coordinates are re-projected per active mushaf type. Bookmarks/collections/tags follow the identical path via `BookmarksDaoImpl` → `collectionsRepository`/`collectionBookmarksRepository`.

**Manual sync:** pull-to-refresh → `canTriggerSync` guard (`isConfigured && authState.value is AuthState.Success`) → `graph.quranDataService.triggerSync()` — fire-and-forget; `BookmarksFragment.onRefreshBookmarks()` immediately clears the spinner since "progress and completion are owned by the underlying sync engine".

**Logout:** row tap → `signOut()` (non-susping wrapper launching `logout()` in `authActionScope`) → `markLogoutPending()` writes `logout_pending_process_id = <random per-process UUID>` to the `quran_sync` SharedPreferences with `commit()` → `graph.quranDataService.logout()` (managed end-session flow through the browser) → `clearLogoutPending()` in `finally`; exceptions first call `graph.authService.clearError()` then propagate to the screen's `actionError` text.

**Legacy upgrade path:** first launch after upgrading → `QuranDataPresenter.checkPages()` runs `migrateLegacyBookmarks()` (blocking bridge into coroutines) → `LegacyBookmarksMigrator.migrateIfNeeded()` (settings-flag + `Mutex` double check) → snapshot tags/bookmarks/recent pages out of the old SQLDelight `bookmarks.db` via `BookmarksDBAdapter` → normalize → `MobileSyncImporterImpl.importData(PersistenceImportData(...), deleteExisting = false)` writing original timestamps → flag `haveMigratedLegacyBookmarksToMobileSync` set only on success.

## 4. Storage & network

- **SharedPreferences `"quran_sync"`** (`QuranSyncManager` companion): `logout_pending_process_id` (crash-recovery marker) and `dismissed_bookmarks_sign_in_card` (CTA dismissal). Separately, `QuranSettings` holds `haveMigratedLegacyBookmarksToMobileSync`.
- **OAuth tokens:** `org.publicvalue.multiplatform.oidc.tokenstore.AndroidSettingsTokenStore(context)` — token/id-token pairs in Android SharedPreferences; removed on logout recovery.
- **Sync database:** the shared library's SQLDelight `QuranDatabase`, created by `DriverFactory(context).makeDriver()` and handed to `SharedDependencyGraph.init` together with `createMobileSyncStorage(context)`. Its entity surface, visible through the models imported in `QuranSyncRepositoryProvider.kt`/`MobileSyncImporter.kt`: collections, ayah bookmarks, collection↔ayah-bookmark links, ayah highlights (`AyahHighlight`, `AyahHighlightColor`), a single reading bookmark (page or sura/ayah, canonical coordinates), and reading sessions — every mutable row carrying a `PlatformDateTime last_updated` for merge ordering. This DB is now the primary bookmark store; the legacy `bookmarks.db` (SQLDelight `BookmarksDatabase`: bookmarks/tags/last_pages/bookmark_tags) is still provisioned in `BookmarkDataModule.provideBookmarksDatabase()` but serves as migration source and for `BookmarksDBAdapter` readers.
- **Configuration resources (build-time injected):** `quran_sync_oauth_client_id`, `quran_sync_oauth_issuer_url`, `quran_sync_oauth_redirect_scheme`, `quran_sync_environment` — defaults blank in `feature/sync/src/main/res/values/strings.xml`; populated per variant from `oauth.properties` keys `QURAN_OAUTH_CLIENT_ID[_<APPID>|_<VARIANT>|_<FLAVOR>]` etc. Redirect URI pattern: `<scheme>://callback` where scheme falls back to the applicationId; host is fixed as `callback`.
- **Network:** OIDC discovery/token/end-session endpoints at the configured issuer (environment selected prelive vs production by `QuranSyncConfig.appEnvironment`), authorization via external browser with the custom-scheme redirect, and the quran.com sync API — all HTTP traffic lives behind the `com.quran.shared.*` binaries (ktor-based URL building appears as `io.ktor.http.URLBuilder` imports); the Android code makes no direct sync HTTP calls and has no caching layer of its own beyond the local database.
- **Download management:** none — unlike page images/audio there is no WorkManager worker or foreground service for sync (`app/.../worker/` contains only AudioUpdate/MissingPage/PartialPageChecking workers); scheduling is delegated entirely to the mobile-sync engine.

## 5. Why it is built this way ON THIS PLATFORM

- **Browser auth must survive the Activity.** An OIDC round-trip leaves the process (custom tab) and can span configuration changes or process death. That is why the flow factory and the pending operation are owned by an app-scoped manager running on `SupervisorJob + Dispatchers.Main.immediate` behind a mutex, while Activities merely register/unregister via token objects; the code comments state this explicitly ("Activity recreation while the browser is open does not strand the pending login"). A pure-Android alternative would be Credential Manager; this stack chose a KMP OIDC library so iOS shares the exact flow.
- **Offline-first with local writes as source of truth.** The shared graph is constructed eagerly even when unconfigured or logged out, and every DAO write stamps its own `PlatformDateTime` before any network involvement — bookmarks, collections, and reading position keep working fully offline and reconcile later. This matches the platform expectation that a mushaf app must render and record instantly on a subway.
- **Pluggable closed-source-style config.** Like recitation (`RecitationPresenterImpl.isRecitationEnabled() == false` in OSS builds), sync is compiled into every build but disabled at runtime when `oauth.properties` is absent — secrets/clients stay out of the open repo while F-Droid/Play builds differ only by injected resValues. No flavor split was needed.
- **Metro contribution seams instead of module coupling.** `ExtraPreferencesProvider` (@ContributesIntoSet) and `@ContributesBinding MobileSyncRepositoryProvider` let `:feature:sync` add settings UI and swap the entire bookmark persistence backend without `:app` or `:common:bookmark` gaining a compile dependency on the feature (only `BookmarksFragment` touches `QuranSyncManager`). This is the same pattern used for menus, preference rows, and ayah panels across the app.
- **Compose islands inside a View shell.** Settings still uses androidx.preference RecyclerViews; embedding a themed `ComposeView` in `onBindViewHolder` (with `DisposeOnViewTreeLifecycleDestroyed`) buys reactive auth-state updates inside that world without rewriting the settings screen.
- **KMP boundary placement.** Merge semantics, conflict resolution, and server protocol live in quran.com's shared `mobile-sync` artifact; Android contributes only platform drivers (`DriverFactory`, token store, activity-based redirect capture). Platform differences (Android background limits vs iOS background fetch) are absorbed inside the library rather than re-implemented here — which is also why no WorkManager integration exists on the Android side.

## 6. Edge cases & offline behavior

- **Unconfigured build:** every entry point checks `isConfigured`; the settings provider returns early, the activity finishes in `onCreate`, `BookmarksSignInCard` renders nothing (`collectAsState(initial = false)` keeps the first frame empty too), and pull-to-refresh stays disabled.
- **Auth errors:** `AuthState.Error` renders the shared library's message, falling back to the generic `quran_sync_action_error` ("Unable to update sync right now."); thrown exceptions from login/logout land in the same inline `ErrorText`. Button spinners prevent double-submission while `isActionRunning`.
- **Process death mid-logout:** the pending marker carries a per-process UUID; on next launch `clearInterruptedLogoutIfNeeded()` sees a foreign UUID and force-clears tokens via `tokenStore.removeTokens()` under `runBlocking(Dispatchers.IO)`. Same-process redirect activities during normal logout deliberately do not consume the marker (comment-documented distinction).
- **Login with no foreground activity:** `InactiveAuthFlowFactory.createAuthFlow` throws `"Quran sync auth is not registered with a foreground Activity."`, while end-session flows degrade to a silent no-op `InactiveEndSessionFlow` (`canContinueLogout() == false`) so background logout attempts never crash.
- **Interrupted legacy migration:** flag written only after success, so failure retries on next start; `BookmarksWidgetListProvider` independently invokes the migrator before reading data, and import runs `deleteExisting = false` to avoid destroying anything already synced.
- **Offline edits & merges:** every mutation takes a local `Clock.System.now()` timestamp (`DefaultMobileSyncTimestampProvider`), and bulk restore paths (`QuranImportActivity` → `QuranImportPresenter.importData`) carry explicit per-row timestamps into `PersistenceImportData`, preserving history for the engine's conflict resolution.
- **Mushaf-coordinate correctness:** reading bookmarks are stored canonically and translated per current page type through `ReadingBookmarkPageMapper`, because madani/warsh/etc. have different page counts — switching page types does not corrupt the synced position.
- **RTL/locale/accessibility:** back arrow, chevrons, and logout icon use `Modifier.autoMirror()` for RTL flipping; strings ship in ~40 locales (including ar, ur, fa, ps, ug); decorative icons use `contentDescription = null` while the dismiss X gets a real label (`quran_sync_bookmarks_cta_dismiss`); both rows and screens include dark-theme Compose previews.
- **Observations/gaps:** within the code read, the highlights pipeline (`SyncCollectionBookmarksRepository.getHighlightsFlow()/setHighlight()`) has no consumers outside `:feature:sync` yet — verse-highlight syncing is plumbed but not surfaced in the page-rendering UI; and aside from the post-login trigger and pull-to-refresh, no user-visible manual "Sync now" control or periodic Android-side scheduler exists, so ongoing cadence is opaque inside the binary `com.quran:mobile-sync:0.1.18` dependency.
