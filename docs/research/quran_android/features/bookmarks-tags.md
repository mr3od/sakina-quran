# Bookmarks and tags
> How **Quran for Android (github.com/quran/quran_android)** implements this feature. Sources read from a shallow clone @ main (2026-08-23); repo-relative paths cited throughout.

## 1. What the user sees

**Bookmarks tab (index screen).** `QuranActivity` hosts `ui/fragment/BookmarksFragment.kt` as the second tab of its index pager (`QuranActivity.kt:537`, title `R.string.menu_bookmarks`). The screen is a `RecyclerView` (`QuranListAdapter`) fed by `QuranRow`s, plus two embedded `ComposeView`s: a quran.com sign-in card (`feature/sync BookmarksSignInCard`, launches `QuranSyncActivity`) and a Compose empty state ("No bookmarks yet – Tap the bookmark icon to save a page, or long press an ayah to bookmark it.", `res/values/strings.xml:373`). Rows cover, top to bottom: a **reading bookmark** ("last place", single movable page/ayah marker), a **recents** header with up to 3 recently-read pages, then either a flat ayah-bookmark list or tag-grouped sections (`TagHeader` rows + a "Not tagged" bucket).

**Options menu** (`app/src/main/res/menu/home_menu.xml`, wired in `BookmarksFragment.onCreateOptionsMenu`): a Sort submenu with radio items *date added* / *location*, plus checkable *group by tags*, *show recents*, and *show date* (renders `MMM dd, HH:mm` timestamps on rows). All four are persisted preferences.

**Multi-select contextual actions.** Long-press starts a support `ActionMode` owned by `presenter/bookmark/BookmarksContextualModePresenter.kt`; the menu (`res/menu/bookmark_contextual_menu.xml`) offers *tag bookmark(s)*, *edit tag*, *delete*, *new tag*. Which items appear is computed in `BookmarkPresenter.getContextualOperationsForItems()`: edit-tag requires exactly one selected tag header and no bookmarks; tag-bookmark requires bookmarks and no tag headers; delete works on any mix. Delete shows a `Snackbar` with **Undo** for 4 s (`BookmarkPresenter.DELAY_DELETION_DURATION_IN_MS = 4000`); the visible list is optimistically rewritten by `predictQuranListAfterDeletion()` before anything hits the DB. Tapping a row jumps to the page (`jumpTo`) or jumps and highlights the verse (`jumpToAndHighlight` for ayah bookmarks). Pull-to-refresh triggers `QuranSyncManager.triggerSync()` only when signed in (`canTriggerSync`).

**In the reader (`PagerActivity`).**
- Overflow-menu star (`R.id.favorite_item`) toggles the **movable page reading bookmark**: tapping another page moves the marker, showing an "undo/moved" toast for 9 s the first time (`educationTimeout`) then 5 s (`movedTimeout`) — logic in `feature/reading/presenter/ReadingBookmarkPresenter.kt`.
- Long-pressing an ayah raises the floating `AyahToolBar` whose menu (`common/toolbar res/menu/ayah_menu.xml`) has "Bookmark this Ayah"; selecting it swaps the action bar for a full-height overlay containing the Compose **`AyahBookmarkWrapper` bottom sheet** (`feature/ayahbookmark`): the ayah name, a "continue from here" reading-bookmark toggle, the user's collections with per-collection bookmark counts and checkboxes, inline new-collection creation, a Remove-bookmark row with 4 s undo, and a warning banner if you try to detach the last remaining marker.
- Optional **on-page bookmark highlighting**: a `highlightBookmarks` switch in `res/xml/quran_preferences.xml`; when on, bookmarked verses on the visible page are tinted with `HighlightTypes.BOOKMARK` (`R.color.bookmark_highlight`).
- A home-screen **`BookmarksWidget`** lists bookmarks sorted by location via `widget/BookmarksWidgetListProvider.kt`.

## 2. Architecture & key files

- `app/.../ui/fragment/BookmarksFragment.kt` — View-based list UI; injects presenters, converts `BookmarkRawResult` → `QuranRow`s, handles click/CAB callbacks.
- `app/.../presenter/bookmark/BookmarkPresenter.kt` — app-scoped MVP presenter; caches the last `BookmarkRawResult`, subscribes to three change flows in `init{}`, builds row data (`getBookmarkRowData`, `getRowDataSortedByTags`, `generateTagsMapping`), runs deferred deletion.
- `app/.../presenter/bookmark/BookmarksContextualModePresenter.kt` — owns `ActionMode` lifecycle so selection survives configuration changes.
- `app/.../presenter/bookmark/TagBookmarkPresenter.kt` + `app/.../ui/fragment/TagBookmarkDialog.kt` — multi-select tag assignment dialog (checkbox list + "New tag" row); `TagBookmarkFragment.kt` is a `@Deprecated` empty shim kept only so old `FragmentManager` saved state can be discarded after upgrade.
- `app/.../presenter/bookmark/AddTagDialogPresenter.kt` + `AddTagDialog.kt` — create/rename tags with blank/duplicate-name validation.
- `app/.../dao/bookmark/*` (`BookmarkRawResult`, `BookmarkRowData` sealed types), `ui/helpers/BookmarkUIConverter.kt`, `QuranRowFactory`, `QuranListAdapter` — presentation mapping layer.
- **Seam (DAO contracts):** `common/data/src/main/java/com/quran/data/dao/BookmarksDao.kt` (with `BookmarkSortOrder.SORT_DATE_ADDED/SORT_LOCATION`), `RecentPagesDao.kt`, `ReadingBookmarksDao.kt`. Everything above depends only on these interfaces.
- **Implementations:** `common/bookmark/src/main/java/com/quran/mobile/bookmark/model/BookmarksDaoImpl.kt` (translates the sync "collections" model back into the app's legacy `Bookmark`/`Tag` shapes), `RecentPagesDaoImpl.kt`, `ReadingBookmarksDaoImpl.kt` + `ReadingBookmarkPageMapper.kt` (canonical ↔ current page-type conversion).
- **Seam (DI inversion):** `common/bookmark/di/MobileSyncRepositoryProvider.kt` is an interface implemented by `feature/sync/QuranSyncRepositoryProvider.kt`, so `:common:bookmark` never depends on `:feature:sync`; `BookmarkDataModule.kt` wires the bindings. `model/BookmarkCollectionsState.kt` abstracts the `StateFlow<List<CollectionWithAyahBookmarks>?>` source (with a suspend fallback `currentCollectionsWithBookmarks()`).
- `feature/ayahbookmark/...` — Compose sheet: `AyahBookmarkWrapper.kt` (`FrameLayout` hosting a `ComposeView` driven by Molecule `launchMolecule`), `presenter/AyahBookmarkPresenter.kt` (`@AssistedInject` factory per `SuraAyah`, MVI-ish `present(): AyahBookmarkState` + event sink), `state/AyahBookmarkState.kt`, `ui/AyahBookmarkSheet.kt` and friends.
- `app/.../feature/reading/presenter/ReadingBookmarkPresenter.kt` — movable page bookmark with optimistic pending-move state machine.
- `common/toolbar/.../AyahToolBarPresenter.kt` — queries `bookmarksDao.isSuraAyahBookmarked()` (conflated channel, IO dispatcher) to pre-check the toolbar icon.
- `app/.../presenter/quran/ayahtracker/AyahTrackerPresenter.kt` — per-page `bookmarksForPage()` flows drive `HighlightTypes.BOOKMARK` overlays.
- **Migration path:** `app/.../model/bookmark/LegacyBookmarksMigrator.kt` → `LegacyBookmarksDataSource` snapshot → `common/bookmark/migration/LegacyBookmarkMigrationNormalizer` → `importdata/MobileSyncImporter`; legacy reads via `@Deprecated app/.../database/BookmarksDBAdapter.kt` over the SQLDelight `BookmarksDatabase`.

**Key discrepancy vs the brief:** the SQLDelight schema files `common/bookmark/src/main/sqldelight/**/{Bookmark,Tag,BookmarkTag,LastPage}.sq` still exist and define `bookmarks.db`, but they are now **read-only legacy input to a one-time migration** (`BookmarksDBAdapter` is annotated `@Deprecated("Only used for one-time legacy bookmark migration reads")`). Live bookmark/tag/recents persistence lives in the quran.com Kotlin-multiplatform database (`com.quran.shared.persistence.QuranDatabase`, opened in `di/MobileSyncDatabase.kt`), reached only through repository interfaces — and "tags" have become **collections**, each ayah bookmark being a membership row across one default (hidden) collection plus zero or more user collections.

## 3. Data flow

**Bookmarks tab (classic MVP over coroutine flows).**
1. Menu toggles call `BookmarkPresenter.setSortOrder()/toggleGroupByTags()/toggleShowRecents()/toggleShowDate()`, which persist to `QuranSettings` (`SharedPreferences` keys `sortBookmarks`, `groupBookmarksByTag`, `showRecents`, `showDate`) and re-request data.
2. `requestData(canCache)` replays `cachedData` when a fragment re-binds (`bind()` passes `true`), else launches `getBookmarksList()` on a presenter-owned `MainScope`.
3. Reads fan out on `Dispatchers.IO`: `bookmarksDao.tags()` + `bookmarksDao.sortOrder` + `recentPagesDao.recentPages()` + `readingBookmarksDao.readingBookmark()`; `ArabicDatabaseUtils.hydrateAyahText()` decorates each bookmark with verse text from the local Arabic DB (failure swallowed).
4. `BookmarksDaoImpl` derives everything from `BookmarkCollectionsState.collectionsWithBookmarks` (a `StateFlow` fed by the shared sync graph): `toBookmarkCollectionData()` filters out the default collection, picks a representative membership per ayah by newest `lastUpdated`, computes tag ids per bookmark, and derives the mushaf `page` via `QuranInfo.getPageFromSuraAyah` (page is *not* stored). Sorting happens in Kotlin (`sortBookmarks`: location = page→sura→ayah, else timestamp desc).
5. Rows are assembled (`RecentPageHeader` + recents inserted at index 0; optional `ReadingBookmarkHeader`), converted by `BookmarkUIConverter` into `QuranRow`s, and pushed to the fragment via `onNewRawData()`.
6. Liveness: `BookmarkPresenter.subscribeToChanges()` collects `bookmarksDao.changes` (a `Flow<Unit>` emitted whenever the collection state map changes), `recentPagesDao.recentPagesFlow()`, and `readingBookmarksDao.readingBookmarkFlow()`, re-requesting data only while a fragment is bound.

**Delete with undo:** CAB delete → `deleteAfterSomeTime(rows)` → render predicted list → `Single.timer(4s).flatMap { removeItemsObservable() }` → `removeItems()` classifies rows into `tagsToDelete` / `bookmarksToUntag` / `bookmarksToDelete` and calls `removeTags`, `removeBookmarkFromTag`, `removeBookmarks`; Undo disposes the timer. Note the semantics: deleting a tag header removes the *collection* and thereby untags members (they survive under "Not tagged"); deleting a bookmark row inside a grouped list removes only that tag membership unless no tag context was involved.

**Ayah bookmark sheet (Compose/Molecule MVI).** Long press populates `ReadingEventPresenter.ayahSelectionFlow` → `PagerActivity.onContextualActionClicked` sees `cab_bookmark_ayah` → `showAyahBookmarkSheet(startSuraAyah)` adds `AyahBookmarkWrapper(this, suraAyah)` to its overlay. `AyahBookmarkPresenter.present()` collects `collectionsWithBookmarksFlow()` and `readingBookmarkFlow()` as compose state, seeds `checkedCollectionIds` once from existing memberships, and translates `AyahBookmarkEvent`s: `ToggleCollection` mutates a local set (blocking removal of the last one with `showLastPlaceWarning`); `CreateCollection` calls `bookmarksDao.addCollection(name)` (IllegalArgumentException → inline name error); `Done` commits `replaceAyahBookmarkCollections(currentAyah, ids)` plus any reading-marker change in `AppCoroutineScope`; `RemoveBookmark` schedules a cancellable `delay(4s)` job before `deleteAyahBookmark()`. Dismissal reports `isBookmarked` back so `PagerActivity.updateAyahBookmark()` refreshes the toolbar icon.

**Page reading bookmark.** `favorite_item` → `ReadingBookmarkPresenter.togglePageReadingBookmark(page)`: either immediate `togglePageReadingBookmark` (un-bookmark case) or an optimistic `PendingMove` with toast + timeout job that commits `setPageReadingBookmark()`; `unbind()` force-confirms any pending move so process/activity teardown never drops it, and a `pendingMove?.page != page` guard stops stale flow emissions from flickering the icon.

**Highlighting.** Each `AyahTrackerItem` collects `bookmarksDao.bookmarksForPage(tracker.page)`; `onBookmarksChanged()` clears then re-applies `HighlightTypes.BOOKMARK` for `"sura:ayah"` pairs, gated by `quranSettings.shouldHighlightBookmarks()`, drawing over the pre-rendered page image using ayah glyph coordinates.

## 4. Storage & network

- **Legacy DB `bookmarks.db`** (SQLDelight 2.x, `AndroidSqliteDriver` created in `BookmarkDataModule.provideBookmarksDatabase`): tables `bookmarks(_ID, sura?, ayah?, page NOT NULL, added_date)` — page bookmarks are rows with NULL sura/ayah; `tags(_ID, name, added_date)`; `bookmark_tag(bookmark_id, tag_id, added_date)` with `UNIQUE INDEX bookmark_tag_index(bookmark_id, tag_id)`; `last_pages(page UNIQUE, added_date)`. Migrations `migrations/1..3.sqm`; an `AfterVersion(2)` callback seeds `last_pages` from `Settings.lastPage()` inside `runBlocking`. Today this DB is only read by the migrator (`getBookmarksForMigration()` uses `getBookmarksByDateAdded` LEFT JOINed to tags, then `convergeCommonlyTagged()` folds duplicated rows back into one bookmark with merged tags).
- **Live DB:** quran.com shared multiplatform `QuranDatabase` via `DriverFactory(context)` (`di/MobileSyncDatabase.kt`), accessed exclusively through `com.quran.shared.persistence.repository.*` interfaces (`BookmarksRepository`, `CollectionsRepository`, `CollectionBookmarksRepository`, `ReadingBookmarksRepository`, `ReadingSessionsRepository`) provided by `feature/sync/QuranSyncRepositoryProvider` wrapping `com.quran.shared.pipeline.QuranDataService`. Writes go through coarse replace-style operations (`replaceAyahBookmarkCollections(sura, ayah, collectionIds, timestamp)`) rather than fine-grained inserts/deletes, with caller-supplied `PlatformDateTime` timestamps from `MobileSyncTimestampProvider` so offline edits keep deterministic ordering for later server reconciliation.
- **Model mapping:** tag == collection; the `isDefault` collection holds "untagged" bookmarks and is never shown as a tag; ids are strings (legacy numeric ids stringified by `LegacyBookmarkIds`); page is derived, not stored.
- **Recents** are stored as reading sessions keyed by the (sura, ayah) bounds of a page; `RecentPagesDaoImpl` dedupes by page, caps at `MAX_RECENT_PAGES = 3`, prunes invalid/unmappable sessions on every write, and exposes a `Flow` combined with the current `pageType` setting so switching mushaf types re-maps pages.
- **Reading bookmark** is a single row (either page- or ayah-scoped) stored in canonical page coordinates and translated to/from the active page type by `ReadingBookmarkPageMapper` (madani/warsh/etc. differ in page count).
- **Preferences** (`app/.../data/Constants.kt`): `sortBookmarks`, `groupBookmarksByTag`, `showRecents`, `showDate`, `highlightBookmarks`, `hasSeenMovableBookmarkEducation`, `mobileSyncLegacyBookmarksMigrated`; sync-specific flags (dismissed sign-in card) in a separate `SharedPreferences` owned by `QuranSyncManager`.
- **Network:** none on the read/write hot path — everything is local SQLite (offline-first). Sync is explicit or engine-scheduled: `QuranSyncManager.triggerSync()` → `graph.quranDataService.triggerSync()` against quran.com infrastructure, authenticated via OIDC (`org.publicvalue.multiplatform.oidc`) with an activity-registered auth flow; the Bookmarks tab surfaces this as pull-to-refresh plus the sign-in card.

## 5. Why it is built this way ON THIS PLATFORM

- **Process death and rotation.** Presenters are `@SingleIn(AppScope)` singletons that outlive fragments; `BookmarkPresenter` caches the last result and replays it on re-bind, and `BookmarksContextualModePresenter` keeps the `ActionMode` outside the fragment so selection state survives recreation. `MainScope`/Rx `CompositeDisposable`-style lifecycles are managed manually because these classes are not Android components.
- **Offline-first with eventual sync.** A Quran app must work with zero connectivity, so the local DB is authoritative for the UI and the sync engine reconciles asynchronously; the DAO emits `Flow`s so any background sync result repaints open screens without user action. Local-timestamp writes make offline edits mergeable.
- **Undo-by-deferral instead of transactions.** Both deletion paths (Snackbar in the tab, delay-Job in the sheet) defer the destructive write by ~4 s and show optimistic state — cheap, platform-idiomatic safety that avoids confirm dialogs and keeps the DB free of soft-delete columns.
- **Module boundary economics.** Metro DI plus provider interfaces (`MobileSyncRepositoryProvider` consumed by `:common:bookmark`, implemented in `:feature:sync`) let the bookmark core ship without dragging in OAuth/KMP sync code; the app shell reaches the Compose sheet through a small injected wrapper (`AyahBookmarkWrapperInjector`) instead of a module dependency, consistent with how `AyahActionFragmentProvider` panels plug into `SlidingPagerAdapter`.
- **Compose adoption is incremental.** The reader is still Views; the bookmark sheet is a Compose tree hosted in a plain `FrameLayout` overlay, with Molecule letting a non-Lifecycle `present()` function produce state — appropriate because the wrapper controls its own visibility/dismissal rather than relying on ViewModel retention.
- **Image-based pages dictate highlight plumbing.** Since pages are pre-rendered images, "bookmark highlight" requires per-page-width glyph-coordinate lookups and an overlay pass (`AyahTrackerPresenter`), not text styling; hence a dedicated `HighlightTypes.BOOKMARK` channel parallel to SELECTION/AUDIO/NOTE.
- **Home-screen widget constraints.** `RemoteViewsFactory` can't collect Flows, so `BookmarksWidgetListProvider.populateListItem()` uses `runBlocking { migrateIfNeeded(); bookmarksDao.bookmarks(SORT_LOCATION) }` — blocking is acceptable in a widget's binder thread.
- **Rx↔coroutines seam.** Legacy presenters wrap suspend DAO calls in `Single.fromCallable { runBlocking { … } }` on `Schedulers.io()` — a deliberate bridge while the codebase migrates presenter-by-presenter to flows/coroutines.

## 6. Edge cases & offline behavior

- **Duplicate tag names** are blocked twice: client-side in `AddTagDialogPresenter.validate()` (blank or duplicate → error callbacks) and again in `BookmarksDaoImpl.updateTag()` (returns false → duplicate-name UI); `addCollection` throwing `IllegalArgumentException` becomes an inline field error in the sheet's create-collection form.
- **Deleting a tag never deletes verses.** `BookmarkPresenter.removeItems()` routes tag-header deletions to `removeTags` (collection delete ⇒ members become untagged), and `predictQuranListAfterDeletion()` pre-computes which bookmarks will newly appear under `NotTaggedHeader` so the optimistic list matches the post-write reality.
- **Last-marker protection.** `AyahBookmarkEvent.ToggleCollection`/`ToggleReadingBookmark` refuse to clear the final collection or reading marker, showing `LastPlaceWarningBanner` for 3 s instead.
- **Bad data guards.** `RecentPagesDaoImpl` drops pages failing `quranInfo.isValidPage`; `BookmarkUIConverter` coerces an invalid recent page to page 1; `updateBookmarkTags` ignores blank/unknown bookmark and tag ids; `BookmarksDaoImpl.removeTags` only deletes ids still known locally (safe against concurrent sync removals).
- **Migration robustness.** `LegacyBookmarksMigrator.migrateIfNeeded()` is pref-gated, double-checked inside a `Mutex`, runs off-main, never deletes legacy rows (`deleteExisting = false`), and returns false on exception so it retries next launch; the widget triggers it too, guaranteeing migrated data regardless of entry point.
- **Stale-emission and teardown races.** `ReadingBookmarkPresenter` keeps a `pendingMove` guard so a slow DB flow can't flip the just-toggled icon, and confirms pending moves in `unbind()`; `AyahBookmarkPresenter` seeds `checkedCollectionIds` exactly once (`didSeedCollectionIds`) so later sync updates don't clobber in-progress edits, and picks the newest membership as the representative when a bookmark sits in several collections.
- **Hydration failures degrade gracefully:** `hydrateAyahText` try/catches and returns un-decorated bookmarks rather than failing the screen.
- **Locale/RTL:** verse/page labels come from `QuranNaming` (Arabic-aware), tag lists are sorted by the DB (`ORDER BY name ASC`), and dates use a locale-default `SimpleDateFormat` behind the opt-in `show date` flag; the list layout relies on standard Android layout mirroring.
- **First-run vs upgrade:** fresh installs never touch `bookmarks.db` meaningfully (empty snapshot short-circuits migration) and see the Compose empty state; upgrading users get their old tags/bookmarks/recents imported into collections on first boot (`QuranDataPresenter` kicks `migrateIfNeeded()`), while the deprecated `TagBookmarkFragment` shim quietly discards obsolete fragment state. Sign-in-gated sync UI hides itself until auth is available (`canTriggerSyncFlow` disables pull-to-refresh).
