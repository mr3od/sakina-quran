# Display & accessibility settings
> How **Quran for Android (github.com/quran/quran_android)** implements this feature. Sources read from a shallow clone @ main (2026-08-23); repo-relative paths cited throughout.

## 1. What the user sees
A single settings screen with categorized rows: Display (Arabic UI toggle, appearance, background style, orientation lock + landscape sub-toggle, translated sura names, night mode group), Reading (page type, page info overlay, marker popups, bookmark highlighting, volume-key navigation), Translation (translation manager launcher, ayah-before-translation, dyslexic font, ayah and translation text-size sliders), Download (prefer streaming, download amount, audio manager), and an Advanced entry point.

## 2. Architecture & key files
- `app/src/main/java/com/quran/labs/androidquran/ui/fragment/QuranSettingsFragment.kt` — `PreferenceFragmentCompat`; inflates `R.xml.quran_preferences`, field-injects `pageTypes: Map<String, PageProvider>` and `Set<ExtraPreferencesProvider>` (:33-37), appends extra rows sorted by `order` (:99-101).
- `app/src/main/res/xml/quran_preferences.xml` — declarative catalog: `use_arabic_names`, `prefs_app_theme`, `prefs_lock_orientation` with dependent `prefs_landscape_orientation` (`android:dependency`), `prefs_sura_translated_name`, `prefs_overlay_page_info`, `prefs_display_marker_popup`, `prefs_volume_key_navigation`, `SeekBarAyahTextSizePreference` (max 40, default 15) and `SeekBarTranslationTextSizePreference`.
- `app/.../data/Constants.kt` — canonical key strings (`PREF_LOCK_ORIENTATION`, `PREF_AYAH_TEXT_SIZE`, `PREF_USE_DYSLEXIC_FONT = "useDyslexicFont"`, `PREF_SURA_TRANSLATED_NAME`, `PREF_USE_VOLUME_KEY_NAV`, etc.).
- `app/.../ui/preference/` — custom widgets: `SeekBarPreference.kt` base plus the four subclasses, `QuranListPreference.java`, `DataListPreference.java`, `QuranHeaderPreference.kt`.
- `app/.../ui/util/TypefaceManager.kt` — `getDyslexicTypeface(context)` lazily loads `OpenDyslexic.otf` from assets (:42-45).
- Consumers: `util/QuranSettings(.java)` accessors (e.g. `wantDyslexicFontInTranslationView()`, :114), `util/OrientationLockUtils`, `ui/translation/TranslationAdapter.kt`.

## 3. Data flow
Most rows are plain persisted checkboxes/list preferences read later by presenters and views through `QuranSettings`. Special-cased handlers live in `onCreatePreferences`: the Arabic toggle is *not* persisted — clicking it computes a new locale list (`LocaleListCompat.forLanguageTags("ar-EG")` to enable, stripping all `ar` tags — falling back to `"en"` — to disable) and calls `AppCompatDelegate.setApplicationLocales`, i.e. Android's per-app language API. The theme row delegates to `ThemeUtil.setTheme`; the translation/audio manager rows launch activities; `PREF_PAGE_TYPE` routes to `PageSelectActivity`; `key_prefs_advanced` opens `QuranAdvancedPreferenceActivity`; any unhandled click falls through to injected `ExtraPreferencesProvider.onPreferenceClick(preference)`. Text-size sliders persist on stop and are picked up by `TranslationAdapter.refresh(quranSettings)` when fragments resume.

## 4. Storage & network
All persistence is SharedPreferences behind `SettingsImpl` implementing the `common/data` `dao.Settings` interface; nothing in this screen hits the network directly (the translation/audio managers it launches do their own catalog fetches). The Arabic toggle additionally relies on AppCompat's per-app locale storage rather than a quran-app preference key. The dyslexic font ships as a bundled asset (`OpenDyslexic.otf`), so no download is required to enable accessibility typography.

## 5. Why it is built this way ON THIS PLATFORM
The screen is the integration point for the app's plugin-style architecture: because feature modules cannot statically depend on `:app`, they contribute settings rows at runtime via Metro-injected `ExtraPreferencesProvider` sets (sorted by `order`) instead of editing the XML — the same pattern used for menu items and ayah-action panels. Using `AppCompatDelegate.setApplicationLocales` for "use Arabic names" instead of a boolean flag means the whole UI, not just sura labels, switches language and RTL layout direction using the platform's per-app language mechanism (backported through AppCompat), which also keeps system settings and the app consistent. Orientation lock hides itself entirely when `OrientationLockUtils.isOrientationLockSupported` reports unsupported hardware behavior (e.g. foldables/unusual configurations) rather than presenting a no-op switch. Volume-key navigation is implemented as a reading-time preference consumed by `PagerActivity` key handling because it must intercept hardware keys only while the pager is visible.

## 6. Edge cases & offline behavior
Everything works offline; sliders and toggles apply on next fragment refresh without restarts (except mushaf/page-type changes, which intentionally relaunch the task). Dyslexic typeface caching (`dyslexicTypeface ?: run {...}`) avoids repeated asset decoding across RecyclerView rebinding in `TranslationAdapter` (:396). Marker popups (`displayMarkerPopup`) and page-info overlays degrade silently when coordinate databases for the current width bucket are missing. Because the Arabic toggle rewrites the locale list destructively (removes every `ar` tag), users with mixed multi-language lists get a normalized list back; defaulting to `"en"` guarantees the app never ends up with an empty locale list.
