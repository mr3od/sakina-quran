# Home-screen widgets
> How **Quran for Android (github.com/quran/quran_android)** implements this feature. Sources read from a shallow clone @ main (2026-08-23); repo-relative paths cited throughout.

## 1. What the user sees
Two launcher widgets. The **bookmarks widget** (`app/src/main/res/xml/bookmarks_widget_info.xml`: min 250x110dp, resizable horizontally and vertically, 30-minute `updatePeriodMillis`) shows an app icon, a search button, a "go to Quran" button, a jump button, and a scrollable list of saved bookmarks (title, sura metadata, star icon) with an empty state. The **search widget** (`res/xml/search_widget_info.xml`, `res/layout/search_widget.xml`) is a compact button strip: open app, search, jump to latest page, jump to a chosen ayah/page.

## 2. Architecture & key files
Everything lives in `app/src/main/java/com/quran/labs/androidquran/widget/`. `BookmarksWidget` (an `AppWidgetProvider`) builds `RemoteViews` and binds a `RemoteViewsService`; `BookmarksWidgetService.onGetViewFactory` returns `BookmarksWidgetListProvider`, a `RemoteViewsFactory` that pulls its collaborators (`BookmarksDao`, `QuranRowFactory`, `LegacyBookmarksMigrator`, `QuranInfo`) by calling `applicationComponent.inject(this)` in `init {}`. `BookmarksWidgetSubscriber` is `@SingleIn(AppScope)` and watches bookmark changes; `BookmarksWidgetUpdater`/`BookmarksWidgetUpdaterImpl` (bound in `di/module/widgets/BookmarksWidgetUpdaterModule.kt`) check for placed widgets via `AppWidgetManager.getAppWidgetIds(ComponentName(...))`. `SearchWidget` is a pure static `RemoteViews` provider with no data.

## 3. Data flow
`BookmarksWidget.onUpdate` attaches four immutable `PendingIntent`s (icon -> `QuranDataActivity`, search -> `SearchActivity`, go-to-Quran -> `QuranDataActivity` with `ShortcutsActivity.ACTION_JUMP_TO_LATEST`, jump -> `ACTION_JUMP_TO`), then `setRemoteAdapter(R.id.list_view_widget, serviceIntent)` plus a `setPendingIntentTemplate` using `QuranDataActivity.ACTION_OPEN_PAGE` (`FLAG_MUTABLE`, so the launcher can stamp per-row extras) and `setEmptyView`. Row taps are resolved in `QuranDataActivity` (L491-503), which routes `ACTION_JUMP_TO_LATEST` to the last-read page and `ACTION_JUMP_TO` to the jump dialog. Bookmark edits reach the widget without user action: `BookmarksWidgetSubscriber.subscribeBookmarksWidgetIfNecessary()` collects `bookmarksDao.changes` on a `MainScope()` and calls `updateBookmarksWidget()`, which is just `notifyAppWidgetViewDataChanged` — the service then re-queries.

## 4. Storage & network
No network. Rows come from the SQLDelight-backed `BookmarksDao.bookmarks(BookmarkSortOrder.SORT_LOCATION)` (common/bookmark), mapped to display rows by `QuranRowFactory.fromBookmark`. `BookmarksWidgetListProvider.populateListItem()` first runs `legacyBookmarksMigrator.migrateIfNeeded()` inside a `runBlocking`, so a legacy-DB install self-migrates the first time the widget renders. `RecentQariManager`-style prefs are not involved; the only persisted widget state is Android's own app-widget ids.

## 5. Why it is built this way ON THIS PLATFORM
`RemoteViews` cannot host a real `RecyclerView`, so a scrollable list requires the `RemoteViewsService`/`RemoteViewsFactory` pair, and row clicks must go through a single `PendingIntentTemplate` (individual rows can't carry their own PendingIntents) — which is why `ACTION_OPEN_PAGE` is `FLAG_MUTABLE` while the static buttons are `FLAG_IMMUTABLE` (Android 12+ requirement). The subscriber indirection exists to avoid holding a Flow subscription (and DB observers) alive for a widget nobody has placed: it only subscribes when `checkForAnyBookmarksWidgets()` is true, and `onDisabled` cancels the scope. Push-on-change plus `notifyAppWidgetViewDataChanged` beats the 30-minute polling period for freshness.

## 6. Edge cases & offline behavior
Empty bookmark list renders `R.id.empty_view` via `setEmptyView`. Multiple widget instances are handled by looping over `appWidgetIds` in `onUpdate` (each gets a uniquely-`Uri`-tagged service intent) and by the updater broadcasting to all ids. The Flow subscription is guarded by an `isSubscribed` flag so `onEnabled`/app-start don't stack collectors, and `onDisabledBookmarksWidget` cancels the scope to stop updates when the last widget is removed. `runBlocking` inside `onDataSetChanged` blocks the widget service's main thread during the (one-time) legacy migration; the list provider reports `hasStableIds() = false`, so rows rebind wholesale on every data change. Fully offline: bookmarks are local, and all buttons deep-link into already-downloaded app surfaces.
