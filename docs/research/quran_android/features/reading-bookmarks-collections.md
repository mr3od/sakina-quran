# Reading bookmarks (movable collections)
> How **Quran for Android (github.com/quran/quran_android)** implements this feature. Sources read from a shallow clone @ main (2026-08-23); repo-relative paths cited throughout.

## 1. What the user sees

There are two distinct surfaces that share one storage model: a **movable "reading bookmark"** ("where you left off" — exactly one at a time) and **collections** of ayah bookmarks (the successor to the legacy "tags").

**Page-level reading bookmark (star in the toolbar).**
- The pager toolbar has a `favorite_item` menu item whose icon flips between `ic_favorite` / `ic_not_favorite` (`app/src/main/java/com/quran/labs/androidquran/ui/PagerActivity.kt`, `refreshBookmarksMenu()`). Tapping it calls `ReadingBookmarkPresenter.togglePageReadingBookmark(currentPage)` (`PagerActivity.kt` `onOptionsItemSelected`).
- Because a reading bookmark is *singular*, tapping the star on a different page **moves** it. The move is optimistic but not immediately durable: a dark bottom-anchored snackbar appears with Undo, rendered by Compose into the activity's content view (`PagerActivity.showReadingBookmarkMovedToast()`, view built by `createReadingBookmarkToastView` in `app/.../ui/readingbookmark/ReadingBookmarkToastView.kt`, composable `ReadingBookmarkMovedToast.kt`). Titles: `"This is a movable reading bookmark"` (first ever save), `"Bookmark moved from X"`, or `"Bookmark added"`; body copy explains *"Saving a reading bookmark replaces your old one. To save multiple ayahs, long press an ayah and add it to a collection."* (`app/src/main/res/values/strings.xml` lines 377–382).
- **One-time education**: `QuranSettings.markMovableBookmarkEducationSeen()` (`app/.../util/QuranSettings.java`) returns whether this is the first presentation and flips per-installation pref `hasSeenMovableBookmarkEducation` (`app/.../data/Constants.kt` `PREF_HAS_SEEN_MOVABLE_BOOKMARK_EDUCATION`). First presentation gets the long copy plus a Dismiss icon (contentDescription "Dismiss") and a 9 s timeout (`educationTimeout`); later saves get the short "moved" toast with 5 s timeout (`movedTimeout`) — see `feature/reading/presenter/ReadingBookmarkPresenter.kt`.
- The snackbar sits above the audio bar (or above the navigation bar) via an insets listener in `showReadingBookmarkMovedToast()`.

**Ayah bookmark sheet (collections + toggle).**
- Long-pressing an ayah and choosing `cab_bookmark_ayah` in the contextual menu opens the sheet: `AyahMenuItemSelectionHandler` → `PagerActivity.showAyahBookmarkSheet(startSuraAyah)` → instantiates `AyahBookmarkWrapper(this, suraAyah) { isBookmarked -> ... }` inside the activity's full-screen `overlay` FrameLayout.
- The sheet (`feature/ayahbookmark/src/main/kotlin/com/quran/mobile/feature/ayahbookmark/ui/AyahBookmarkSheet.kt`) is a Material 3 `BottomSheetScaffold` peeked at half screen height, draggable to full height. Fixed header: drag handle, sura/ayah title, a "Done" action, and a highlighted **Reading bookmark row** (`ReadingBookmarkRow.kt`) with a Switch — subtitle reads "Where you left off", "Currently at X" (toggle off, bookmark elsewhere), or "Will move from X" (toggle on, bookmark elsewhere).
- A scrollable list of **collection rows** (`CollectionRow.kt`: custom checkbox, name, bookmark-count label) each toggled by tap; a pinned footer holds: an amber **last-place warning banner** ("Keep in at least one place - to delete, use Remove bookmark below.", `LastPlaceWarningBanner.kt`, auto-hides after 3 s), a "+ New collection" trigger that expands into an inline text field with Cancel/Create (spinner while submitting), and a red "Remove bookmark" row.
- Removing shows an in-sheet "Bookmark removed / Undo" toast (`BookmarkRemovedToast.kt`) with a 4 s undo window; Done, swipe-to-dismiss, or expiry closes the sheet. The sheet is **auto-save**: even swiping away persists pending checkbox/toggle changes (`AyahBookmarkWrapper` fires `AyahBookmarkEvent.Done` on any transition to hidden).
- On dismiss, PagerActivity refreshes the ayah toolbar's bookmarked state (`updateAyahBookmark` → `ayahToolBar.setBookmarked`). The bookmarks index screen also renders the current reading bookmark as a row (`ui/helpers/QuranRowFactory.kt` `fromReadingBookmarkHeader`/`fromReadingBookmark`, string `reading_bookmark` = "Reading Bookmark").
- Localized in ~45 locales (`feature/ayahbookmark/src/main/res/values-*`); Compose previews cover dark theme and an Arabic (`locale = "ar"`) variant (`ui/AyahBookmark.kt`).

## 2. Architecture & key files

Feature module `:feature:ayahbookmark` (Compose + Molecule + Metro, deps only on `:common:data`, `:common:pages`, `:common:ui:core`):
- `feature/ayahbookmark/.../AyahBookmarkWrapper.kt` — View interop entry: a `FrameLayout` hosting a `ComposeView`; Metro field-injection via `di/AyahBookmarkWrapperInjector.kt` (implemented by `PagerActivity`, wired in `di/component/activity/PagerActivityComponent.kt`). Hosts M3 `BottomSheetScaffold`, runs the presenter through **Molecule** (`launchMolecule(RecompositionMode.ContextClock)`) into a `StateFlow` collected by the UI.
- `presenter/AyahBookmarkPresenter.kt` — `@AssistedInject` MVVM presenter; `@AssistedFactory Factory.create(currentAyah: SuraAyah)`. A single `present()` @Composable builds all state and returns an `eventSink`. Timers live here: `undoDefaultTimeout = 4s`, `remainingItemWarningTimeout = 3s`.
- `state/AyahBookmarkState.kt` — `@Immutable AyahBookmarkState`, `AyahBookmarkCollectionItem`, sealed `AyahBookmarkCollectionCreationState` (Inactive/Active(name,isSubmitting,hasNameError)), sealed `AyahBookmarkEvent` (ToggleReadingBookmark, ToggleCollection, StartCreatingCollection, CollectionNameChanged, CreateCollection, RemoveBookmark, UndoRemoveBookmark, Done).
- UI pieces: `ui/AyahBookmark.kt` (renders sheet XOR removed-toast), `ui/AyahBookmarkSheet.kt`, `ui/ReadingBookmarkRow.kt`, `ui/CollectionRow.kt`, `ui/NewCollectionRow.kt`, `ui/RemoveBookmarkRow.kt`, `ui/LastPlaceWarningBanner.kt`, `ui/BookmarkRemovedToast.kt`, `ui/AyahBookmarkColors.kt` (hardcoded light/dark warning palette), `ui/icons/AyahBookmarkIcons.kt`.

DAO layer (`:common:bookmark` implementing interfaces in `:common:data`):
- `common/data/src/main/java/com/quran/data/dao/ReadingBookmarksDao.kt` — seam interface: `readingBookmarkFlow()`, `setPageReadingBookmark`, `setAyahReadingBookmark`, `deleteReadingBookmark`, `isPageReadingBookmark`, `togglePageReadingBookmark`.
- `common/bookmark/.../model/ReadingBookmarksDaoImpl.kt` — `@SingleIn(AppScope)` impl backed by the mobile-sync KMP library: `com.quran.shared.persistence.repository.readingbookmark.repository.ReadingBookmarksRepository` + `model/ReadingBookmarkPageMapper.kt` (coordinate translation) + `time/MobileSyncTimestampProvider.kt`.
- `common/bookmark/.../model/BookmarksDaoImpl.kt` — collections side: `addCollection`, `replaceAyahBookmarkCollections`, `deleteAyahBookmark` (= membership replaced with empty set), `collectionsWithBookmarksFlow`, and the legacy tag↔collection adapter layer (`BookmarkCollectionData`, default-collection filtering).
- `common/bookmark/.../model/BookmarkCollectionsState.kt` — small interface exposing `collectionsWithBookmarks: StateFlow<List<CollectionWithAyahBookmarks>?>`; implemented by `feature/sync/.../QuranSyncRepositoryProvider.kt` (`SyncBookmarkCollectionsState`) over `QuranSyncManager.quranDataService` from `com.quran.shared.pipeline` (`com.quran:mobile-sync` 0.1.18, gradle/libs.versions.toml line 25/147).
- DI bindings: `common/bookmark/.../di/BookmarkDataModule.kt` (provides repositories + collections state from `MobileSyncRepositoryProvider`; also still constructs the legacy SQLDelight `BookmarksDatabase`), `common/bookmark/.../di/MobileSyncDatabase.kt` (`QuranDatabase(DriverFactory(context).makeDriver())`), `di/module/application/DatabaseModule.kt`.

Page-type seam:
- `common/bookmark/.../model/ReadingBookmarkPageMapper.kt` — maps pages between the current mushaf edition and canonical **madani** storage coordinates using per-edition `QuranInfo` from the injected `Map<String, PageProvider>` and `FALLBACK_PAGE_TYPE`.

App-side page-bookmark orchestration:
- `app/src/main/java/com/quran/labs/androidquran/feature/reading/presenter/ReadingBookmarkPresenter.kt` — `@ActivityScope` MVP-ish presenter combining `currentPageFlow` with `readingBookmarksDao.readingBookmarkFlow()`, owning optimistic `PendingMove(page, previousBookmark, timeoutJob)` state and a `Screen` interface implemented by PagerActivity.
- Toast views under `app/.../ui/readingbookmark/` (Compose `ComposeView` added directly to `android.R.id.content`).
- Migration path (why old tables still ship): deprecated `app/.../database/BookmarksDBAdapter.kt` → `app/.../model/bookmark/LegacyBookmarksDataSource.kt` → `common/bookmark/.../migration/*` and `importdata/MobileSyncImporter.kt` used by `LegacyBookmarksMigrator` / `BookmarkImportExportModel`.

## 3. Data flow

**Opening the ayah sheet:** long-press ayah → `cab_bookmark_ayah` → `showAyahBookmarkSheet(suraAyah)` → `AyahBookmarkWrapper.init` injects `AyahBookmarkPresenter.Factory`, creates `ComposeView`, `factory.create(currentAyah)`; `launchMolecule { presenter.present() }` produces a hot `StateFlow<AyahBookmarkState>`.

**Initial seeding (inside `present()`):**
1. `bookmarksDao.collectionsWithBookmarksFlow().collectAsState(null)` — flow chain: `QuranDataService.collectionsWithBookmarks` (shared sync graph, live SQLite observation) → `SyncBookmarkCollectionsState.collectionsWithBookmarks` (`stateIn(Eagerly)`) → `BookmarksDaoImpl.collectionsWithBookmarksFlow()` mapping to app models `ReadingCollectionBookmarks`.
2. `readingBookmarksDao.readingBookmarkFlow().collectAsState(null)` — `combine(repository.getReadingBookmarkFlow(), pageMapper.pageTypeFlow())` → `toReadingBookmark()` → `distinctUntilChanged().flowOn(Dispatchers.IO)`; deliberately kept **cold** so new collectors start from current DB value (comment in `ReadingBookmarksDaoImpl`).
3. A `LaunchedEffect` seeds `checkedCollectionIds` once (`didSeedCollectionIds` guard): any collection containing this (sura, ayah) is pre-checked; `hasExistingCollections` records whether it was already saved.
4. `showRemoveBookmarkButton = hasExistingCollections || readingBookmark == this ayah`.

**User events → effect:**
- `ToggleCollection(id)`: pure in-memory set arithmetic; if unchecking would leave zero save locations while a persisted bookmark exists and the reading-bookmark toggle is off, sets `showLastPlaceWarning = true` instead (auto-clears after 3 s via `LaunchedEffect`+`delay`).
- `ToggleReadingBookmark`: local `mutableStateOf` flip with the mirrored guard (can't disable the last remaining location).
- `StartCreatingCollection/Cancel/NameChanged/CreateCollection`: `Active` editor state; `CreateCollection` launches `bookmarksDao.addCollection(name)` (`CollectionsRepository.addCollection` → `quranDataService.addCollection`), auto-checks the new collection id; persistence-level rejection (`IllegalArgumentException`, e.g. duplicate name) becomes inline `hasNameError` ("That collection name is unavailable."), `CancellationException` is rethrown.
- `Done` (also fired on swipe-dismiss): launches on the injected `AppCoroutineScope` (`AppCoroutineScope` qualifier, app-wide CoroutineScope) — marks dismissed so the wrapper hides the sheet, then durably writes `bookmarksDao.replaceAyahBookmarkCollections(currentAyah, checkedIds)` and reconciles the reading bookmark: set via `readingBookmarksDao.setAyahReadingBookmark` or delete via `deleteReadingBookmark()` only when the toggle differs from persisted reality.
- `RemoveBookmark`: shows the undo toast immediately, cancels any prior removal job, then after 4 s on `appCoroutineScope` runs `bookmarksDao.deleteAyahBookmark(currentAyah)` (membership → empty set) plus `deleteReadingBookmark()` if the global reading bookmark currently points at this same ayah. `UndoRemoveBookmark` cancels the job.

**Write path underneath:** every DAO write wraps `withContext(Dispatchers.IO)` around the shared-library repository call and stamps `timestampProvider.now()` (`MobileSyncTimestampProvider`) so writes carry server-compatible timestamps; `BookmarksDaoImpl.replaceBookmarkCollections` delegates to `bookmarksRepository.replaceAyahBookmarkCollections(sura, ayah, collectionIds, timestamp)` returning `.changed`. State then propagates back reactively through the same flows — no manual cache invalidation anywhere in app code.

**Page-star move flow:** toolbar tap → `ReadingBookmarkPresenter.togglePageReadingBookmark(page)` → either immediate `readingBookmarksDao.togglePageReadingBookmark(page)` (un-bookmarking persisted state), cancel of an in-flight pending move (re-tap ≡ Undo), or a new optimistic `PendingMove`: icon set selected instantly, toast shown, `timeoutJob` on `appCoroutineScope` confirms after 5/9 s via `setPageReadingBookmark(page)`. `unbind(screen)` force-confirms any pending move so process/activity exit never drops the bookmark nor leaks the toast. Stale-flow flicker is suppressed by checking `pendingMove?.page != page` before reflecting DAO emissions.

## 4. Storage & network

- **Primary store — shared mobile-sync database.** `common/bookmark/di/MobileSyncDatabase.kt` builds `com.quran.shared.persistence.QuranDatabase` via `DriverFactory(context).makeDriver()` (SQLDelight, Kotlin-multiplatform artifact `com.quran:mobile-sync` 0.1.18). It owns collections, collection↔ayah-membership rows, the single reading-bookmark row (`AyahReadingBookmark{sura,ayah,lastUpdated}` or `PageReadingBookmark{page,lastUpdated}` in canonical madani coordinates), highlights, and reading sessions. App code never sees table names — only repository interfaces — so schema detail stops at the model boundary (`PlatformDateTime`, `fromPlatform().toEpochMilliseconds()/1000` conversion to legacy unix-second timestamps).
- **Legacy store — `bookmarks.db`.** SQLDelight `BookmarksDatabase` declared in `common/bookmark/src/main/sqldelight/com/quran/mobile/bookmark/{Bookmark,Tag,BookmarkTag,LastPage}.sq` (tables `bookmarks(_ID,sura,ayah,page,added_date)`, `tags(_ID,name,added_date)`, `bookmark_tag`, `last_pages(page)`), created by `BookmarkDataModule.provideBookmarksDatabase` with an `AfterVersion(2)` migration callback that copies `settings.lastPage()` into `last_pages`. Since the cutover, `BookmarksDBAdapter` is `@Deprecated("Only used for one-time legacy bookmark migration reads")` — the old DB is now a read-only migration source, and the new store's always-present `isDefault` collection subsumes the old untagged-bookmark list (see `BookmarkCollectionData.defaultCollectionId` filtering in `BookmarksDaoImpl`).
- **Preferences.** `hasSeenMovableBookmarkEducation` in per-installation SharedPreferences (`Constants.PREF_HAS_SEEN_MOVABLE_BOOKMARK_EDUCATION`, written/read by `QuranSettings.markMovableBookmarkEducationSeen()`); page type comes from `Settings.pageType()` observed via `settings.preferencesFlow()` in the page mapper.
- **Backup/export.** Reading bookmarks serialize to CSV-ish rows via `common/data/.../model/bookmark/BackupReadingBookmark.kt` (`type=ayah|page, sura, ayah, page, timestamp`, `getCommaSeparatedValues()` → `"reading_bookmark, $sura, $ayah, $page, $timestamp"`), consumed by `app/.../model/bookmark/BookmarkCSVAdapter.kt` / `BookmarkImportExportModel.kt`; imports are normalized by `common/bookmark/.../importdata/BookmarkBackupImportNormalizer.kt` (which validates/relocates coordinates using `ReadingBookmarkPageMapper.isValidSuraAyah`/`sourcePageToStoragePage`).
- **Network.** No feature-specific endpoints or downloads. The same tables feed cloud sync when the user signs in: `feature/sync/QuranSyncManager.kt` eagerly creates the shared `AppGraph` ("so local sync-backed data is available in configured, unconfigured, logged-in, and logged-out states"), talks to quran.com infrastructure over ktor/OIDC, and stores tokens via `AndroidSettingsTokenStore` / `createMobileSyncStorage(context)`. Bookmarks therefore work fully offline and sync opportunistically; there is no retry/backoff logic in this feature itself.

## 5. Why it is built this way ON THIS PLATFORM

- **Incremental Compose inside a View shell.** The reader is a classic View-based `PagerActivity`; rather than converting, the sheet ships as a leaf `:feature:ayahbookmark` module injected through the `AyahBookmarkWrapperInjector` seam (same pattern as `ExtraScreenProvider`/`AudioBarInjector`). The wrapper is a plain `FrameLayout` dropped into the existing `overlay` container — reusing the exact mechanism `QariListWrapper` uses — which sidesteps dialog-window/focus complications and lets the activity keep handling back/action-bar state.
- **Molecule instead of a ViewModel.** `launchMolecule(RecompositionMode.ContextClock)` turns the `present()` composable into a cold-started `StateFlow` driven by the Choreographer. That keeps one mental model (state-in-composition) while avoiding recomposition of the whole tree on every frame, and avoids lifecycle-owner plumbing a `ViewModelProvider` would need for an assisted parameter (`currentAyah`). The presenter holds no Android context; strings resolve through injected lambdas (`suraAyahNameResolver`) so previews work without Robolectric.
- **Auto-save + undo instead of confirm dialogs.** Android convention (Material snackbars) and touch ergonomics: the sheet commits on Done *or* swipe-away, with a 4 s undo window for destructive removal. The comment in `AyahBookmarkWrapper` is explicit — "this is an auto-save sheet - a swipe-to-dismiss still needs to persist pending changes".
- **Canonical madani storage coordinates.** The app supports four mushaf editions chosen at build time (flavor `pageType`), where "page N" means different content. Storing bookmarks against madani numbering and translating through `ReadingBookmarkPageMapper` (with clamping and nearest-page heuristics over `QuranInfo.getPageBounds`) is what makes a bookmark survive a user switching to warsh/qaloon/naskh — a constraint essentially unique to image-based mushaf apps; tests pin it (`ReadingBookmarksDaoImplTest`: "stores canonical page when current page type differs", "flow remaps page bookmark when page type changes").
- **Shared KMP persistence.** Moving bookmarks/collections into `com.quran.shared.persistence` lets the iOS/desktop siblings and the Android app share one schema and one sync pipeline, and makes cloud sync a property of the data layer rather than a feature — the app just observes flows. Local-first remains intact because the graph is created eagerly regardless of auth state.
- **Insets & edge-to-edge realities.** The non-modal toast must dodge three-button navigation, gesture bars, cutouts and the audio bar; hence the `WindowInsetsCompat` padding/margin dance in `showReadingBookmarkMovedToast()` and `imePadding()`/`displayCutoutPadding()` on the sheet. A web implementation would solve positioning with CSS safe-area/env variables and would likely use a real modal with explicit Save; native here optimizes for one-handed interruption mid-recitation.

## 6. Edge cases & offline behavior

- **"Last place" invariant enforced twice**: in-memory guards in the event sink (`ToggleCollection`/`ToggleReadingBookmark`) refuse to leave the ayah with zero locations and surface `LastPlaceWarningBanner` for 3 s; actual deletion requires the explicit `RemoveBookmark` row. Deletion of the reading bookmark also deletes the ayah from *all* collections only through the explicit remove path.
- **Duplicate collection names**: surfaced by the persistence layer as `IllegalArgumentException`, mapped to an inline error string; `CancellationException` carefully rethrown in both create and replace paths so structured-concurrency cancellation isn't swallowed.
- **Undo races**: `RemoveBookmark` cancels any previous `removalJob` before starting a new one; `ReadingBookmarkPresenter` keys `PendingMove` by page so taps on other pages confirm the earlier move implicitly, and re-tapping the same page acts as Undo without touching the DAO.
- **Lifecycle safety**: `onResume` binds `readingBookmarkPresenter` to `currentPageFlow`, `onPause` unbinds; `unbind` confirms any pending move first ("leaving the activity neither drops the bookmark nor leaves its toast attached without a timeout"). The toast view is manually removed/re-added to `android.R.id.content` to avoid stacking duplicates.
- **Missing/degenerate data**: invalid stored pages clamp to page 1 when rendering the bookmarks list (`QuranRowFactory.fromReadingBookmark` `takeIf(quranInfo::isValidPage) ?: 1`); `ReadingBookmarkPageMapper.clampPage` walks bounds until a valid page exists; unknown page types fall back through `resolveCurrentPageType` → fallback flavor → madani.
- **Offline-first**: everything is local SQLDelight; no network call exists in the feature, so airplane mode only defers sync. External writes (e.g. from a background sync) arrive reactively — covered by the test "reading bookmark flow emits external mobile sync writes".
- **First-run vs upgrade**: fresh installs have no `bookmarks.db` legacy rows; upgrades run the one-time legacy→mobile-sync importer (`LegacyBookmarksMigrator`, normalizers in `common/bookmark/.../migration`), and the education toast appears exactly once per installation on first movable-bookmark save.
- **Theming/a11y/i18n**: hardcoded warning palette with light/dark variants (`AyahBookmarkColors`); collection rows expose `Role.Checkbox` via `Modifier.toggleable`, decorative icons have `contentDescription = null` while actionable ones (dismiss) do not; ~45 translated string files, Arabic-locale Compose preview, and RTL-safe layouts (row-based, no absolute alignment).
- **Test coverage**: `common/bookmark/src/test/.../ReadingBookmarksDaoImplTest.kt` (Robolectric, real in-memory DB) pins coordinate remapping, replace semantics, and delete-no-op notification behavior; `app/src/test/.../feature/reading/presenter/ReadingBookmarkPresenterTest.kt` and `fakes/FakeReadingBookmarksDao.kt` cover the move/undo/education state machine.
