# Dual-page and split translation layout
> How **Quran for Android (github.com/quran/quran_android)** implements this feature. Sources read from a shallow clone @ main (2026-08-23); repo-relative paths cited throughout.

## 1. What the user sees
On a wide device held in landscape (or an open foldable used vertically), the reader shows two consecutive mushaf pages side by side like an open physical book, right page first (Arabic reads right-to-left). Settings > Dual Screen offers two checkboxes: "dual page mode" (`prefs_dual_page_enabled`, defaulted from `R.bool.use_tablet_interface_by_default`) and, dependent on it, "split page and translation" (`prefs_split_page_and_translation`). With split enabled, switching the reader to translation mode stops showing two translation pages; instead a single screen is divided between the mushaf image on one half and the scrolling translation of that same page on the other, ordered according to whether the current page is a "right" or "left" book page.

## 2. Architecture & key files
- `app/src/main/java/com/quran/labs/androidquran/data/Constants.kt` — keys `PREF_DUAL_PAGE_ENABLED = "useDualPageMode"` (:74) and `PREF_SPLIT_PAGE_AND_TRANSLATION = "splitPageAndTranslation"` (:63).
- `app/.../util/QuranUtils.java` — `isDualPages(context, qsi, isValidFoldableDeviceAndOpen)` (:114): dual mode requires `QuranScreenInfo.isDualPageMode` (screen `maxWidth > 960`, see `util/QuranScreenInfo.kt`:62) AND landscape orientation or an open foldable; only then does it read the preference.
- `app/.../ui/helpers/QuranPageAdapter.kt` — `FragmentStatePagerAdapter` whose count becomes `totalPagesDual` (ceil(pages/2)) and which instantiates `TabletFragment.newInstance(page, mode, isSplitScreen)`.
- `app/.../ui/fragment/TabletFragment.kt` — hosts a custom `TabletView` containing two `QuranImagePageLayout`s (ARABIC mode) or two `QuranTranslationPageLayout`s, or one of each in split mode (`initSplitMode`, :151).
- `app/.../ui/PagerActivity.kt` — `updateDualPageMode()` (:348) re-evaluates on configuration changes and remaps the current position via `quranInfo.mapSinglePageToDualPage/mapDualPageToSinglePage`.
- `app/src/main/java/androidx/viewpager/widget/NonRestoringViewPager.java` — vendored ViewPager fork told `setIsDualPagesInLandscape(...)` (PagerActivity :501).

## 3. Data flow
PagerActivity computes `isDualPages` once at startup and again whenever orientation/foldable state changes, then rebuilds the adapter with `PageMode.DualScreenMode.Arabic/Translation/Mix` (`makePageMode()` in QuranPageAdapter). Each pager position maps to a spread; `TabletFragment.onAttach` receives `pageNumber`, `mode`, `IS_SPLIT_SCREEN` extras and gets its collaborators from a per-spread `QuranPageComponent` built with the exact pages array (`intArrayOf(pageNumber, pageNumber+1)`, or just one page when splitting). Rendering goes through `QuranPagePresenter` (bitmaps via `QuranPageLoader`) and `TranslationPresenter` (verses from downloaded translation DBs) into the two child views; ayah interaction is centralized in `AyahTrackerPresenter` fed by `AyahImageTrackerItem`s (or `AyahTranslationTrackerItem`s) built in `getAyahTrackerItems()`. In split mode a single `AyahSplitConsolidationTrackerItem(imageItem, translationItem)` represents the page so highlights resolve against whichever half was touched; scroll position of the translation half is persisted in `onSaveInstanceState`.

## 4. Storage & network
Both flags live in the default SharedPreferences behind `QuranSettings`/`SettingsImpl`. Page halves still load full single-page bitmaps from the width-bucketed local mushaf cache (`widthParam`/`tabletWidthParam` in `QuranScreenInfo.kt`) — dual mode reuses the tablet-width image bucket rather than downloading separate spreads. If a page's images are missing, `mainView.showError(...)` plus `quranPagePresenter.downloadImages()` triggers the standard `QuranDownloadService` flow; nothing about dual mode adds new network endpoints.

## 5. Why it is built this way ON THIS PLATFORM
Pages are pre-rendered images, so "two pages" cannot be a CSS-style reflow: it must be two `ImageView`s sharing one fragment, and the whole pager must halve its item count so swipe gestures move one *spread* at a time. That is why the decision lives in three layers — a hardware predicate (`maxWidth > 960` + orientation/foldable state), a user preference, and an adapter that rewrites positions — because rotating the device mid-read has to keep the reader on the same ayah, hence the explicit `mapSinglePageToDualPage` remapping and `LAST_WAS_DUAL_PAGES` saved-state check (PagerActivity :420). The foldable clause exists because an open vertically-held foldable behaves like a book even while Android reports portrait. Split mode deliberately collapses the pager back to one item per page (`isDualPagesVisible = isDualPages && !(isSplitScreen && isShowingTranslation)`, QuranPageAdapter :121) because a split screen already consumes the whole viewport with one page.

## 6. Edge cases & offline behavior
Invalid page numbers in ARABIC mode get `NoOpImageTrackerItem` instead of an image tracker (TabletFragment :283). When the active page type supplies a custom `PageViewFactory` (`pageProviderFactoryProvider.providePageViewFactory(quranSettings.pageType)`), the fragment sets `isCustomArabicPageType` and skips binding `QuranPagePresenter` entirely — bitmap-based dual logic is bypassed for non-image page types. `isQuranOnRight = (pageNumber + quranInfo.skip) % 2 == 1` (:153) keeps odd/even book sides correct despite skipped front-matter pages, so the image always lands on the physically correct side. Offline, everything except first-time image downloads works locally; translation halves simply show whatever translations are already installed, and download errors surface as a retry overlay on the affected half.
