# Share and copy verses
> How **Quran for Android (github.com/quran/quran_android)** implements this feature. Sources read from a shallow clone @ main (2026-08-23); repo-relative paths cited throughout.

## 1. What the user sees
Long-pressing an ayah on a mushaf page pops up the floating `AyahToolBar` (`common/toolbar/src/main/java/com/quran/page/common/toolbar/AyahToolBar.kt`, which inflates `common/toolbar/src/main/res/menu/ayah_menu.xml`). It offers bookmark, translate, play-from-here, and a nested *share* submenu with three entries: **link** (`cab_share_ayah_link`), **text** (`cab_share_ayah_text`), **copy** (`cab_copy_ayah`). Copy shows an "ayah copied" toast; text opens the system share chooser; link shows an indeterminate progress dialog until a short quranapp.com URL resolves, then opens the same chooser.

## 2. Architecture & key files
All actions funnel through `PagerActivity`'s inner `AyahMenuItemSelectionHandler` (`app/src/main/java/com/quran/labs/androidquran/ui/PagerActivity.kt`, ~L1828), which reads the current `AyahSelection` from `ReadingEventPresenter.currentAyahSelection()` and derives `start`/`end` `SuraAyah`. Two Metro-injected helpers do the work: `util/ShareUtil.kt` (formatting, clipboard, `ACTION_SEND` intents) and `util/QuranAppUtils.kt` (short-link generation). Verse text comes from `model/translation/ArabicDatabaseUtils.getVerses()`; display strings come from `data/QuranDisplayData`. The menu lives in the reusable `:common:toolbar` module so other UI shells can reuse it.

## 3. Data flow
`shareAyah(start, end, isCopy)` has two branches. If translation mode is active with loaded translations, it calls `updateLocalTranslations()` to snapshot `QuranAyahInfo` from the visible page's `AyahTracker`, then `ShareUtil.getShareText(activity, ayahInfo, translationNames)` renders Arabic plus each translation prefixed by its resolved translator name, with footnotes stripped via `footnoteCognizantText(...)` mapped to empty spans. Otherwise it subscribes to `arabicDatabaseUtils.getVerses(start, end)` (RxJava3, `.filter { it.isNotEmpty() }`, `observeOn(AndroidSchedulers.mainThread())`) into a `CompositeDisposable` and hands the `List<QuranText>` to `copyVerses`/`shareVerses`. `shareAyahLink` shows `showProgressDialog()` and subscribes to `quranAppUtils.getQuranAppUrlObservable(getString(R.string.quranapp_key), start, end)`.

## 4. Storage & network
Verse text is read from the on-device Arabic SQLite database; `PagerActivity.shareAyah` gates on `quranFileUtils.hasArabicSearchDatabase()` and otherwise raises `showGetRequiredFilesDialog()` (the database is a downloadable asset). Copy writes plain-text `ClipData` labelled with the app name via `ClipboardManager`. The only network call is a form-encoded `POST` to `Constants.QURAN_APP_ENDPOINT` (`http://quranapp.com/note`) using raw `HttpURLConnection` (a literal `// TODO: use OkHttp` sits above it), returning JSON whose `url` field is the short link; fallback base is `http://quranapp.com/<sura>`.

## 5. Why it is built this way ON THIS PLATFORM
The output format encodes Muslim citation convention: verses wrapped in `{ ... }` with attribution in `[Surat X: N]` brackets (`ShareUtil.getShareText`). `ArabicDatabaseUtils.getAyahWithoutBasmallah()` strips the basmallah that is baked into verse 1 text so quoted text stays faithful; multi-verse shares append locale-formatted inline ayah numbers (`NumberFormat.getNumberInstance(locale)`). quranapp.com links only support ranges within one sura, so `QuranAppUtils.getQuranAppUrlObservable` clamps a cross-sura range to the last ayah of the start sura. Because the link call is blocking HTTP, it runs on `Schedulers.io()` behind a progress dialog instead of being folded into the download service used for large assets.

## 6. Edge cases & offline behavior
Copy/share of text works fully offline once the Arabic database exists; only link generation needs connectivity. On HTTP error or empty response the observable still completes with the fallback per-sura URL; if the whole chain errors, `onError` merely dismisses the progress dialog (no user-facing failure message). A null selection aborts the handler (`return false`). Translation branch requires `lastSelectedTranslationAyah != null`; there is an in-code admission (`PagerActivity` L1884) that this back-and-forth with the translation fragment is temporary and sharing belongs outside `PagerActivity`. Footnote markers are deliberately dropped ("remove footnotes for now"), and cross-sura links silently degrade to within-sura links.
